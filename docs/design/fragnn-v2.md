## 1. 診断（なぜ enveda_v1 で落ちたか）

事実:
- fragnn の結果: v3_c1 +0.0261 [+0.0027, +0.0490]、v3_c2 0、enveda_v1 −0.0079 [−0.0320, +0.0141]（better 15 / worse 19）、v3_c2n +0.0133 [−0.0117, +0.0396] → enveda_v1 の下限 < −0.02 で不採用【確認: `outputs/local_eval/fragnn_v3_check.json`】
- 学習の群は **正例も負例もすべて T（train の構造）の中**。負例 = ±10 ppm 窓で `allowed & ~val_rows & is_trainstruct` の行【確認: `scripts/train/fragnn_train.py` 9 行目の docstring、`prepare()` の `B.negative_csr(..., allowed & ~val_rows & is_trainstruct)`】。つまり学習中に T の外の候補を一度も見ていない【確認: `docs/research/trainstruct-bias.md` §0】
- 入力は断片の説明の特徴（ピークごと 17 次元 F_PEAK + 対の点 F_PAIR + スペクトル 3 次元 F_SPEC）だけで、構造の ID・埋め込み・参照スペクトルの近さは入っていない【確認: `scripts/train/fragnn_bench.py` `build_model`・`_pair_features_py`・`pack_spectra`】→ 「T の会員であること」を直接覚える入力の道は無い
- enveda_v1 の悪化 19 分子はすべて 1 位が同じ分子式の異性体に替わり、新しい 1 位のうち 14 が T、19 すべてが train の構造。正解は T に 0【確認: #120 2026-11-17T16:03:26Z、PR #143】。ただし基準の割合は数えていない
- 学習の無い MetFrag-lite でも、train の構造のおとりは T の外のおとりより高く出る: d_dom v3_c1 +0.187 [+0.063, +0.302]、v3_c2 +0.167、enveda_v1 +0.258 [+0.115, +0.393]、v3_c2n −0.013（none）【確認: #178 コメント、`outputs/local_eval/ddom_metfrag_ci.json`】
- fragnn 自身の上乗せ Δ_seen（fragnn − MetFrag-lite）は v3_c1 −0.009・e180_c2k +0.028 で区間は 0 をまたぐ（none）。enveda_v1 −0.035 [−0.086, +0.016]【確認: #146】

読み（仕組み）【推測、ただし上の事実と矛盾しない唯一の筋として】:
1. 断片の説明の点そのものに **スペクトルに依らない構造の「説明しやすさ」（断片の数・質量の密さ・切りやすさ）** が入っており、train の構造（ライブラリ由来）は T の外の構造よりその値が系統的に高い（d_dom が学習なしでも higher_train）
2. fragnn は群の中の全員が T なので、この「構造の事前の説明しやすさ」の差を **群の中で打ち消す必要を学ばない**。fragnn は特徴をより強く使う（blind 比 +0.32〜+0.39）ので、この差も一緒に増幅して並びに出す
3. 正解が T の外・おとりが T の enveda_v1 では、この差がそのまま正解の不利になる。v3_c1 で得なのは、v3_c1 の窓の中での差の効きが小さいか、スペクトルの証拠の得が上回るから【推測】
4. #146 が none なのは「fragnn が MetFrag-lite より余計に偏る」とは言えない、という意味で、上の 1〜3（偏りは特徴にもともとあり、fragnn はそれを消さない）とは両立する
- 言えないこと: 19 分子のうち何分子がこの仕組みによるか（分子ごとの分解はしていない）

## 2. 提案（1 つ）: fragnn v2 = spectrum-contrast centering

変更（構造の変更、1 つだけ）:
- 候補 c の点を `z(s, c) = f(s, c) − mean_{m=1..M} f(s'_m, c)` にする。s'_m は **c と同じ ±10 ppm 窓に正例を持つ、c とも s の正例とも別の構造の学習スペクトル**（同じイオン化モード、seed 固定の無作為選択。窓に無ければ同じモードの無作為の学習スペクトルを使い、前駆体の値だけ c の質量に置き換える）。M = 2 で固定
- 学習の損失・群（正例 1 + 負例 K_CAND、T の中）・止め方（`unified_rel_bad_v2`、EVAL_EVERY 2,000、STOP_REL 0.005、STOP_PATIENCE 5、上限 300,000）・内部検証・drop_keys・モデルの形（FragNN）は #120 のまま。z を logit として同じ softmax の損失に入れる
- 推論: holdout の各候補に同じ規則で M = 2 の対照スペクトル（学習スペクトルだけから、seed 固定）を当てて z を出す。holdout のスペクトル・正解は対照に使わない
- 狙い: z は「この候補はどのスペクトルでも説明しやすい」分を引くので、構造の事前の説明しやすさ（= T と T の外の差の元、上の 1）を学習時から消す。学習の群が全部 T でも、引き算は候補ごとに効くので T の外の候補にもそのまま効く【推測】
- v3_c1 を失わない理由【推測】: 正解のスペクトルに固有の断片の一致（f(s, c) − f(s', c) の差）は残る。fragnn の得（blind 比 +0.39）の大半はスペクトル依存の部分のはず
- 直せないもの: (a) 正解のスペクトル固有の一致そのものが T のおとりより弱い分子、(b) 窓に T の外の候補が無い・正解が窓に無い分子（v3_c2 は 0 のまま）、(c) 断片の生成器が正解の断片を作れない構造、(d) 「train の構造は正解になりやすい」という class 1 の事前情報（v2 はこれを使わない設計）

## 3. 事前登録（ドラフト）
- 変更: 上の z の 1 点だけ。M = 2、対照スペクトルの選び方・seed（SEED のまま）はこの文で固定
- 回数: 学習 1 回・採点 1 回（4 集合同時）。失敗しても定数を変えて回し直さない（回し直しは新しい事前登録）
- 止め方: fragnn_train.py の統一規則のまま。使う重み = 内部検証の損失が最良（holdout・LB で選ばない）
- 採点の前の条件（#178 の規則）: Δ_dom = d_dom(v2) − d_dom(MetFrag-lite) が v3_c1・e180_c2k のどちらでも `higher_train` でないこと。満たさなければ採点しない
- 採否: 対照 `score+prior+frag` に対し `score+fragnnv2+prior+frag` の (新 − 対照) の bootstrap 95% 下限が v3_c1・v3_c2・enveda_v1・v3_c2n のすべてで ≥ −0.02、かつ v3_c1 の下限 > 0（bootstrap は #120 と同じ回数・seed）
- 記録だけ（採否に使わない）: fragnn（v1）との差、blind 対照との差、d_seen・d_dom（5 集合）、enveda_v1 の悪化分子の内訳（#143 の A/B/C 表）、z の引き算の大きさ（mean f(s',c) の T / T の外での平均）
- 漏れ: 対照スペクトルは学習スペクトル（drop_keys 後）だけから取る assert を足す

## 4. 費用の見込み【推測、未測定】
- v1 の実績: 4.78 step/s（MPS）、best は 106k ステップ、内部検証 1.2076、ram_peak 3.94 GB、MPS 1.10 GB【確認: #120】
- v2 は 1 群あたり特徴の計算が (1 + M) = 3 倍、forward も 3 倍。特徴が律速なら ≈ 1.6 step/s → 106k ステップで約 18 h（収束が 1.5 倍延びれば 27 h）。v1 の経過時間の上限 10.04 h を超えるので、事前に速度測定（#121 と同じ型）をして上限を決め直す必要がある
- メモリ: 対照スペクトルの番号の表が増えるだけで、prep の断片は同じ構造なので増えない → peak RSS 4〜5 GB の見込み

## 5. 採らなかった案
- 負例に T の外を混ぜる（allpool）だけ: 正例が全部 T なので「T の外 = 負」の近道ができる（#148 の指摘）。正例を T の外に足す fragnn-x は 222〜232 構造しかなく取り下げ（#149）
- FREEZE（rr_v3 型、T の候補の位置を固定）: 推論時の後付けで学習の変更ではない。enveda_v1 で T のおとりが上がるのは止められるが、v3_c1 の得の一部（T の候補どうしの並べ替え）も止める【推測】。#146 の規則で門なし FREEZE は設計の前提にしないと決まっている
- 交差 fold の out-of-fold 学習: fragnn は構造の ID を入力に持たないので、記憶の道を断つ効果は小さい見込み【推測】。費用は fold 数倍

## 6. 未決の点
