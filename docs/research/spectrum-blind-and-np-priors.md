### S1. Separability Is Not Alignability（arXiv:2610.37979）
- 書誌: Musielinski, Teh, Koyama, Dubrawski、2026-10-27 投稿（v1）、NeurIPS 2026 ワークショップ RPS のポスター。https://arxiv.org/abs/2610.37979 、DOI https://doi.org/10.48550/arXiv.2610.37979 。論文のライセンスは CC BY 4.0（arXiv の表示）。**確認**（arXiv の HTML 版 v1 の全文を読んだ）
- spectrum-blind の作り方（§5、付録 I）。**確認**
  - 主な対照は「期待スコア」。学習済みの採点器をそのまま使い、公式の候補リストの各候補 m を、学習 fold の 194,119 本のスペクトルで平均した点 ρ̄(m) = E_s[ρ_θ(s, m)] で並べる。問い合わせのスペクトルも測定条件も使わない。大域コサインの点は線形なので、学習スペクトルの埋め込みの平均と候補の埋め込みの内積がそのまま厳密な値になる。MaxSim は線形でないので、学習スペクトルから重複なしで 16,384 本を抜いて平均する
  - 副の対照は、エンコーダの出力を学習平均に置き換え、付加イオンと衝突エネルギーだけは問い合わせのものを残す
  - 報告するのは Δ0 = MRR_blind − MRR_rand と Δs = MRR_full − MRR_blind。ランダムの MRR は候補数 K について H_K / K の平均（MassSpecGym の検査分割で 0.024）
- 候補集合の事前分布の測り方（§5 の式 (3)、付録 I の式 (5)）。**確認**（式の導出は著者の主張）
  - 候補リストを負例にした InfoNCE の最適解は、log p(m)/q(m)（ライブラリ化合物かデコイかの事前の対数オッズ、スペクトルに依らない）と、スペクトルと構造の点ごとの相互情報量（PMI）の和になる。バッチ内の負例（r = p）なら事前の項は消えるが、ベンチマークの候補リスト（q ≠ p）では残る
- 表の数値（表 1 左・表 4、凍結 DreaMS の対照学習、MassSpecGym の検査分割）。**主張**
  - ChemBERTa: バッチ内の負例で MRR 0.147（blind 0.020、Δ0 −0.004）、候補リストの負例で 0.211（blind 0.147、Δ0 +0.122、Δs 0.064）
  - MoLFormer: バッチ内の負例で 0.227（blind 0.018、Δ0 −0.006）、候補リストの負例で 0.303（blind 0.169、Δ0 +0.144、Δs 0.135）
  - 候補リストで学習すると、blind の MRR は MoLFormer で +0.151 [0.125, 0.178]、ChemBERTa で +0.126 [0.105, 0.148] 上がる。full の上がり幅（+0.077、+0.064）より大きい。blind の上がり分は、ランダムより上の full MRR の 0.52 と 0.66 にあたる
  - 改良版（表 1 右）: シミュレーションで事前学習した後に実スペクトルで学習し、MaxSim で採点すると 0.463（fresh）。候補リストの目的関数を足すと 0.566 になるが、blind の MRR も 0.070 と 0.085 上がる（§6）
  - 著者の注意（§5）: ベンチマークのデコイは、汎化を主張するための厳しい学習・検査の分割の手順に従っていない

## 3. 次に v3 で測る案（1 つ）: FPNet の点から「スペクトルに依らない分」を引く（`pmi` の段）

### 3.1 中身
- S1 の式 (3) にならい、縮小版の score の段 `fp[bits] @ z`（z は fold モデルの分子ごとのロジット）を `fp[bits] @ (z − z̄)` に置き換える。z̄ は、その集合の採点に使う fold モデルの学習分子（そのモデルの学習から外した fold と、パネルの天然物を除いた分子）について、`scripts/cv/local_fold0_logits.py` の `molecule_logits` と同じ前処理で作ったロジットの平均。点が線形なので、`fp[bits] @ z̄` は S1 の期待スコアの対照（全学習スペクトルでの厳密な平均）にあたる
- 引く量の係数は 1 で、式 (3) の分解から決まる値。選んだ値ではないので、ほかの係数は試さない
- 対照 = `score,prior,frag`、新 = `pmi,prior,frag`（score の段だけを置き換える。prior の `POOLPOP_MU = 0.15`、frag、dedup、窓 ±10 ppm は変えない）
- 記録だけするもの（採否には使わない）: 4 集合で `fp[bits] @ z̄` だけで並べた値（FPNet の blind の MRR）と、ランダムの MRR（窓の大きさから H_K / K）。項目 2 の pop の blind と横に並べる

### 3.2 採否の規則
- 4 集合規則のまま。`scripts/cv/frag_v3_check.py` の `judge` を import する。4 集合（v3_c1・v3_c2・enveda_v1・v3_c2n）すべてで、`train_eval.bootstrap_diff`（分子ブートストラップ 2,000 回、seed 0）の (新 − 対照) の 95% 区間の下限が −0.02 以上、かつ v3_c1・v3_c2 の少なくとも片方で下限が 0 より大きいときだけ採用する。1 集合でも欠ければ不採用。結果が良くても悪くても規則どおりに記録する
- v3_c2 は #92 で見つかった 3 件（m_00010・m_00020・m_00112）を含んだまま判定する。3 件を除いた値は記録だけする。作り直した v3_c2 が先にできていれば、Issue に書いてからそちらで判定する
- 事前登録: 計算を始める前に、新しい Issue に「z̄ の作り方、係数 1、対照、規則、1 回だけ実行」を書き、独立レビューを通す。不採用でも係数や z̄ の作り方を変えて測り直さない

### 3.3 リークの扱い
- z̄ にはホールドアウトの問い合わせを使わない（問い合わせ自身の平均を取る形は、隠れテストでは使えるが、採否が問い合わせの分布に寄りかかるので採らない）。使うのは、その集合を採点する fold モデルの学習分子だけ。ホールドアウトの正解はそのモデルの学習から外れているので、z̄ にも入らない
- ほかの段（prior の pop、frag）は今と同じものを使うので、新しいリークは入らない
- 隠れテストとの違い: z̄ は train の分布の平均で、enveda の装置の分布とはずれる。v3_c1 のクエリは enveda-180、v3_c2n は enveda を優先しているので、そのずれの一部は v3 にも入っている。それでも隠れテストでの効果の推定ではない

### 3.4 なぜこの案か、なぜ天然物らしさの点（S4）ではないか
- 自前の部品（式 (3) に基づく採点の補正）で、定数を新しく持ち込まない。採点器が中に持つ事前分布を初めて測ることになり、項目 2（外の prior）と対になる
- S4 の NP-likeness を使う案は次の理由で後回しにする: (a) 公開モデルの学習に使った天然物の一覧が無く、ホールドアウトの正解（天然物）を外して作り直せない。外すなら Ertl の方法を自前で実装し、LOTUS（S6、非営利・表示）からホールドアウトの正解を除いて学習することになる。(b) 今の並びに混ぜるには重み（定数）が要る。同点だけを崩す形なら定数は要らないが、項目 1 では並びが変わった分子が 1〜3 しか無く、同じように効く余地が無い恐れがある。(c) S6 の `np_likeness` は既知の天然物の 153,964 件にしか値が無い
- 見込みのコスト（**未計測**）: train の学習分子ぶんの FPNet の推論が CPU で要る。train.parquet は必要な列だけを row group ごとに読み、`vm_stat` で空きを確かめてから動かす。GPU は使わない
