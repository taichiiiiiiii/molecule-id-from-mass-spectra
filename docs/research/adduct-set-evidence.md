## 1. 結論（先に）

- **v3 の 4 集合では測らない。** 理由は 3 つ（§6）:
  1. 届く伸びの上限が MDE に届かない、または測りたいものを測れない。rank 1 を固定する置き場所（公開ノートと同じ）では、正解が 2 位以下にあるものを全部 2 位に上げる「完全な予言者」でも、上限は v3_c1〈C1〉 0.0165（v3_c1 の MDE の最小 0.0176 より小さい）、v3_c2〈C2〉 0（正解がプールに無いので、定義上 0）、enveda_v1 0.0224、v3_c2n 0.0639。v3_c2n はクエリのスペクトルの 98.6% が timsTOF 以外（全クエリが timsTOF の分子は 1.5%）で、付加イオンの組は enveda の測りかたではなくライブラリごとの登録のしかたを表す。enveda-180 で学んだ確率をそこに当てても、測りたいもの（test と同じ測りかたの組）を測れない
  2. 公開ノートの作者自身のオフラインの数が、ほぼ 0 か負。rank 1 を固定したとき、作者が抜いておいた enveda-180 1,478 分子で −0.0008、NP の例 227 分子で +0.0023。盤面では +0.003（作者も「1 分子が 2 位→1 位に動く約 0.004 より小さく、再実行で ±0.002 揺れる」と書いている）。上限の何割かしか取れない段なので、v3 で見込める伸びは MDE よりずっと小さい
  3. v3 のクエリは、可視の test と付加イオンの出かたが違う（§5）。多量体（[2M…）の付加イオンを持つ分子が v3_c1 42.5% / v3_c2 40.5% / enveda_v1 32.0% なのに、可視の test では 0%。付加イオンが 1 種だけの分子は v3_c1 33.5% なのに、可視の test では 73.0%。分子あたりのスペクトルは 6.26 本と 3.03 本。v3 で測っても、test での効き目を表さない
- **次の手**（どれを採るかは計画で決める。§7）: (a) 独立の段にせず、自前のランカー（#158 (B) 系統）の特徴量の 1 つとして入れる。「候補の構造から予測した付加イオンの組」と「クエリの組」の対数尤度を特徴にし、fold-safe に学習する。測るのは事前登録した診断提出で、v3 では決めない。(b) §5 の「v3 のクエリは test と付加イオンの出かたが違う」を、ほかの段（複数のスペクトルを合わせる段）の v3 の読みにも効く落とし穴として、別の Issue にする候補
- 測る案を出すなら守る条件（今は実行しない）は §6.3 に書いた
