## 2. S1 の要点（落とし穴ごと。数値は S1 の表から、確認）

- **P1 事前学習の近い類縁体（§4.1）**: 指紋 → 分子の復号器を外部の大きな分子集合で事前学習するとき、検査の分子を 2D InChIKey の完全一致だけで除くと、近い類縁体（Tanimoto ≥ 0.7）を覚えて当てる。推奨: 完全一致を全学習から除く。汎化を言うなら Tanimoto ≥ 0.7（ECFP4 2048 ビット）か MCES < 10 も除く。**検査分子と学習集合の最大 Tanimoto で層別した成績を報告する**
- **P2 模擬器・合成データ経由の漏れ（§4.2、表 1）**: 検査も含めて学習した ICEBERG で検査の分子の合成スペクトルを作り MIST を学習すると、検索の R@1 が 67.75%（漏れの無い合成の追加 53.76%、追加なし 9.57%）。推奨: 模擬器はベンチマークの分割を守って学習したものだけを使い、合成データからも検査の分子を除く
- **P3 分子式の漏れ（§4.3、表 2）**: 質量の課題で正解の分子式を使うと、ランダムでも Hit@1 0.43% → 12.98%。検査で学習した分子式の推定器を通すと MIST の Hit@1 26.64% → 35.15%
- **P4 SMILES の正準化の不一致（§5.1、表 3）**: 正解の SMILES は元のライブラリの書き方のまま、おとりは PubChem から取り RDKit で正準化していた。書き方だけで正解が分かり、SMILES の書き方だけを学ぶ分類器で Hit@1 99.66%（直すと 8.2%）、DreaMS + ChemBERTa の整列で 82.41%（直すと 6.70%）。推奨: 正解と候補の全 SMILES を同じ RDKit の正準化に揃える（v1.5 で既定）
- **P5 候補の出どころ・順位の偏り（§5.2、表 3）**: スペクトルを見ずに PubChem の既定の順（付録 A.4 の方法 5: CID の deposition count の多い順）に並べるだけで Hit@1 49.98%。SMILES に立体の印（@・@@）が付いた原子の数で並べる（方法 6。表 3 の (5)。向きは学習集合で決める）だけでも簡単な指紋の基準と同じ程度。正解（スペクトルが測られた分子）は PubChem の一般の分子と分布が違う。v1.5 でも**解決していない**（S1 §7 の限界）。推奨: **入力のスペクトルをすべて定数で隠し、成績が落ちることを確かめる**
- **P6 再利用した部品の実装の誤り（§6.1、表 4）**: MIST の注意のマスクをバッチで誤って足す（`attn += attn_mask`）。ある公開の MIST の重み（vDiffMS）はバッチで推論すると漏れのような高い値を出し、1 本ずつに替えると MIST + MolForge の Top-1 が 31.75% → 10.73%
- **P7 指標の実装のずれ（§6.2、付録 A.6・A.7）**: InChIKey は 14 文字（2D）で比べる。Tanimoto は ECFP4・2048 ビットに固定（半径・ビット数で値が大きく動く、表 10）。MCES は myopic-mces の threshold 15・always_stronger_bound True。区間は 20,000 回の bootstrap の 99.9%

## 5. v3_c1・v3_c2 で測る案（1 つ。この回は実行しない。実行は事前登録とレビューの後の別項目）

P5（出どころだけで当たるか）を、S1 の「スペクトルを見ない基準」の形で、両方の集合で測る。

- 問い: v3_c1・v3_c2 は、スペクトルを見ずに候補の出どころ（とその順）だけで正解に届く形になっていないか。なっていれば、次の自前の部品の伸びを、出どころの群の中だけの比較と並べて報告しなければならない
- v3_c1
  - 候補: `run.py` と同じ窓（±10 ppm、`hide_rule` どおり、`pool_meta.key` で重複除去）
  - 並べ方 B_src: src ∈ {1, 3} の候補を先、src 2 を後。同じ群の中は seed 0 の無作為の順。上位 25
  - 数える: 分子ごとの rr（MRR@25 の 1/順位、25 位の外は 0）、top1。比べる相手は同じ窓のランダムの期待値 E[rr] = (1/K) Σ_{r=1..min(K,25)} 1/r（K = 窓の候補数）
- v3_c2
  - 候補: PubChem チャネルと同じ tier の窓（`scripts/local_eval/pubchem.py` の `Tier.window`、±10 ppm、プールのキーを除く）。重複除去は v3_c1 と同じ考えで canon キーごとに最初の行だけ残す。ただし全候補の canon キーの計算は重いので、raw キー（0.16 ms/分子）で先に重複を除き、正解と同じ分子式の候補だけ canon キーを計算して正解の別名もまとめる（互変異性体は分子式が同じなので取りこぼさない）。K はこの数え方の後の候補数
  - 並べ方は 1 つ: B_tier = tier のファイルの順（窓の中の `pc_smiles` の並び）。S1 の方法 5 は PubChem の CID の deposition count の多い順で、tier の順がそれに当たるかは**未確認**（tier の作り方を読んで、測る前に書く）。S1 の方法 6（立体の印の数）は、§3 で tier の行の立体の印が 0 なので測らない
  - 数える: v3_c1 と同じ rr と、窓のランダムの期待値
- 共通の決まり（測る前に固定する案）
  - 窓に正解が無い分子（v3_c2 で PubChem の窓に正解が無い分子など）は rr = E[rr] = 0 として分母に入れる（n は集合の全分子）。その数も記録する
  - 問題ありの判定: 集合ごとに、Δ0 = rr(B) − E[rr] の分子ごとの差の平均を対の bootstrap 2,000 回（seed 0）で 95% 区間にし、**下限 > 0.05 なら「その集合は出どころの近道を報いる」**。並べ方は集合ごとに 1 つ（v3_c1 は B_src、v3_c2 は B_tier）なので、合わせ方の決まりは要らない。0.05 は「1 分子の順位の変化より大きく、v3 の 200 分子の区間の幅（#146 で約 0.07〜0.10）の半分程度」で選んだ読みの目安で、何かの採否の定数ではない
- 使い道（結果を見る前に固定する）: 「報いる」集合では、以後の新しい部品の報告に (i) 出どころの群の中だけの比較（v3_c1 なら src ∈ {1, 3} の候補だけに絞った MRR の新 − 対照）と、(ii) S1 の推奨どおりスペクトルを定数に替えた対照（入れ替えではない）を必ず並べる。「報いない」集合では記録だけ。どちらでも v3 の採否の規則・定数・対照は変えない
- 最小検出効果の目安: n 200、sd(Δ0) を 0.2 と仮定すると MDE ≈ 2.8 × 0.2 / √200 ≈ 0.04【推測：sd は測っていない】。判定の目安 0.05 はこれより大きい
- 見込み（推測）: v3_c1 は正解が src 1、おとりの約 74% が src {1, 3} なので、B_src はランダムを窓を約 0.74 倍にした程度しか上回らず、「報いない」と見込む。v3_c2 は B_tier が deposition count に近い順を残していれば効きうる。どちらも測っていない
- 資源: v3_c1 は数秒、v3_c2 は tier を mmap で読み、分子式が正解と同じ候補だけ正準化するので数分の見込み、メモリ 2 GB 未満の見込み【推測：測っていない】。train.parquet は読まない。GPU・Kaggle は使わない
