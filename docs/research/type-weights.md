# 型の重み（playbook §4.1、11/26 の到達点）と 12/6 の holdout の判定の書式

Issue #249（親 #228、#195 の A5・B10）。計画 `plan_2026-11-26_night.md` の項目 4。

**結論（先に書く）: 型の重みは置かない。** 隠れテストの型の比率を、LB を使わずに推定できる手元の記録が無い（§2）ので、重みを 1 つに決められない。playbook §4.1 のとおり、**「どの型も −0.02 より悪くしない」の条件だけ**で判定する（§3）。型をまとめた値（重みつき・重みなしの平均）は判定に使わない。

## 1. 決めること（playbook §4.1 の文）

> まとめた値を使うときは型の重みを 11/26 に文書で固定する（根拠は隠れテストの型の比率の推定の幅。LB の値は使わない。比率が分からない間は「どの型も −0.02 より悪くしない」を条件にする）
> — `docs/research/competition-playbook.md` §4.1

- 「型」はチーム内の分け方で、公式の区分ではない（#195 A5 の文）。型の定義は #216（答えの出所 × 参照の有無）: (a) プールにあり・参照あり（C1 型、holdout は v3_c1u_t10）、(b) プールにあり・参照なし・COCONUT（c2n 型、v3_c2nu_t10）、(c) PubChem 層だけ・参照なし（C2 型、v3_c2_t10）、(d) プールにあり・参照なし・enveda の装置（enveda_v1u_t10）、(e) プールに無い・参照あり（dev の評価だけ。holdout には無い）
- この文書は比率の推定と重みの判断、12/6 の判定の**書式**だけを書く。基準（score+prior）の数値は書かない（§3.3）

## 2. 隠れテストの型の比率について手元にある記録

LB の値（Public のスコア・順位、およびそれから逆算した混合の比、例えば #42 の混合の幅）は、playbook §4.1 のとおり**根拠に使わない**ので、ここには引かない。

### 2.1 公式の記述（比率の数は無い）
- Overview: 「既知・新規を問わず、正確な SMILES 表現を生成することを目指す」（`docs/competition/overview.md` 29 行）。型ごとの割合の記述は無い
- Data: 「the file you see is comprised of examples from the training dataset; it will be replaced by the hidden test set during re-run, and will be approximately the same size.」、主催者の確認（756064、David Healey 2026-11-11）「Correct, and the hidden test set has roughly similar size.」（`docs/research/rules-and-deps.md` 66〜68 行）。大きさの記述だけで、型の比率は無い

### 2.2 見える test（400 分子）での数え（#210 A5・#230）
- train との一致（`best_cos ≥ 0.99`、「train の写しらしい」）: **400/400 = 1.000、Wilson 95% [0.9905, 1.0000]**。最良一致の構造がプールの ±10 ppm の窓にある: 400/400（`docs/research/headroom.md` §5）
- 外部ライブラリ（MassSpecGym）との一致（`best_cos ≥ 0.99`）: **0/400、Wilson 95% [0, 0.0095]**、そのうち train に無い構造との一致 0/400。比べる相手が 1 件以上ある分子 315/400（`docs/research/a13-slot-dup.md` §2、`docs/research/headroom.md` §5.1）
- **この 2 つは隠れテストの比率の推定に使えない**: Data の文のとおり見える test は train の例で作られているので、train との一致が全部になるのは作り方からほぼ自明（headroom.md §1.2・§5、a13-slot-dup.md §2 に同じ注意）。もし使うなら「隠れテストも見える test と同じ作り方」という仮定が要るが、Data の文は「hidden test set に置き換わる」と書いており、その仮定を支える記述は無い

### 2.3 dev・holdout の型ごとの分子数（#236）
- dev の B8 の 20 集合（used_b8 = 1）: (a) 789・(b) 787・(c) 788・(d) 745・(e) 792（#236 の結果のコメント issuecomment-7152070482）
- holdout: v3_c1u_t10 394・v3_c2_t10 197・enveda_v1u_t10 373・v3_c2nu_t10 394（計 1,358 行、同じコメント）
- **これは比率の推定ではない**: どちらも型ごとにほぼ同じ数を引く**作り方**で決まった数（B8 は 5 型を揃えて引いた、holdout は v3 と A3a の作り方）で、隠れテストの混ざり方を表さない
- 参考（比率ではなくプールの性質）: fold-0 の hold の構造は、正規化キーで約 99.4% がプールにある（#236 の定義のコメント issuecomment-7150781116 の「読み方の注記」）。train 由来の構造はほぼ全部プールにある、ということで、隠れテストの答えがプールにあるかどうかは言えない

### 2.4 まとめ
- 手元の記録で、隠れテストの型の比率に区間を付けられるものは**無い**。§2.2 の区間は見える test（train の例）についての区間で、隠れテストへは移らない
- したがって比率の推定の幅は、どの型についても実質 [0, 1] のまま（推定できない）

## 3. 判断と 12/6 の判定の書式

### 3.1 重み
- **重みを置かない。** 推定の幅が [0, 1] では、どの重みを置いてもその根拠が書けない（重みを選ぶと、その時点で比率を仮定することになる）
- 型をまとめた値（重みつき平均・重みなしの平均・全分子の MRR）は**判定にも報告の見出しにも使わない**。型ごとの値だけを並べる
- 新しい根拠（LB 以外で、隠れテストの型の比率に区間を付けられるもの。例: 主催者が型の内訳を公表する）が出たときだけ、この文書を別の Issue で改める。holdout・dev の値を見た後に重みを足さない

### 3.2 12/6 の holdout の判定（中間、playbook §4.1 の文のまま）
- 対象: 凍結した版 A（コードの commit hash と特徴の一覧を測る前に Issue に記録）
- 集合と型: v3_c1u_t10（C1 型、(a)）・enveda_v1u_t10（(d)）・v3_c2_t10（C2 型、(c)）・v3_c2nu_t10（c2n 型、(b)）の 4 つ。**C1 と C2 は必ず別々に報告する**
- 条件: 4 集合の**それぞれ**で、Δ_t = MRR@25_t(版 A) − MRR@25_t(score+prior の基準、同じ holdout) **≥ −0.02**。4 つすべてで満たせば「条件を満たす」、1 つでも満たさなければ「満たさない」
  - −0.02 は playbook §4.1 の値のまま（動かさない）
  - 判定は Δ_t の点の値で行う（playbook §4.1 の文は点か区間かを書いていないので、点の値の比較と読む。R1 の「C1 以外の型は平均の差 ≥ −0.02」と同じ読み）。分子単位の対応のある bootstrap の 95% 区間（#247 の評価と同じ: 2,000 回、seed 0、百分位）は記録として併記し、判定には使わない
  - 採否の規則 R1（#208、オーナー承認 2026-11-23。`docs/research/adoption-power.md` の「提案 R1」）との関係: C1 以外の型を「点の Δ ≥ −0.02」で見る線は R1 と同じ。R1 の「v3_c1u_t10 の 95% CI 下限 > 0」は採用（良くなったと言う）の条件で、playbook §4.1 の 12/6 の条件（版 A を最終候補として保持するか）には入っていないので、ここには足さない。最終 2 本の選び方に入れるかは最終 2 本の選び方の規則（#195 B4）で決める
  - 注: v3_c2_t10 は答えを全部プールから隠した集合で、プールだけで並べる基準の MRR は 0 になる作り（headroom.md §2.1 の表の (i-b)・(i-c) の区分のとおり、正解はプールの窓に 0。表の対照は `score,prior,frag` だが、正解がプールに無いので段の構成によらず 0）。そのため Δ ≥ −0.02 はこの集合では作りの上で必ず満たされる。つまりこの条件は C2 型について何も確かめない。C2 型の値は Δ そのもの（と区間）を別に書いて読む
- 結果の書式（Issue のコメント、集合ごとに 1 行、小数 4 桁）:
  - `集合（型）: n ＝ …、基準 score+prior ＝ …、版 A ＝ …、Δ ＝ …（95% 区間 [… , …]、記録用）、条件 Δ ≥ −0.02: 満たす / 満たさない`
  - 最後に「4 集合すべてで満たす / 満たさない集合: …」の 1 行。型をまとめた値の行は書かない
- 結果の使い方（playbook §4.1 のまま）: 満たせば版 A を最終候補の 1 つとして保持する。満たさなくても dev での開発は続けてよいが、holdout の値・分子別の結果は開発に使わない。両方の holdout（12/6・12/11）で満たさない場合の代替は最終 2 本の選び方の規則（#195 B4）に入れる。その規則の期日は playbook §4.1・§5 では 12/5、#195 の B4 の行では「12/7 まで」と食い違っており、早い方（12/5）に合わせる

### 3.3 基準の数値（まだ計算しない）
- **ここで固定する数値は −0.02 だけ**。playbook §4.1 は「11/26 に数値を文書で固定する」と書くが、基準の値を出すには holdout で score+prior を計算する必要があり、計画（`plan_2026-11-26_night.md` の項目 4・冒頭の注）のとおり G1 の後に回す（11/26 の到達点のうちこの部分は遅れる）
- score+prior の基準の 4 つの値は、G1（playbook §4 の承認）の後に 1 回だけ計算して #249 に書く（playbook §4.1 のとおり、この 1 回は holdout の 2 回の上限に数えない）。今夜は計算しない・開かない
- 書く値: 集合ごとの n と基準の MRR@25、計算した commit、submission CSV の sha256
- 基準の構成について記録: playbook §4.1 は「score+prior」と書き、#247 の dev の対照は `score,prior,frag`。12/6 の基準は playbook の文のとおり `score,prior` とする。dev の報告の対照（#247）とは別のものなので、混ぜて書かない

### 3.4 dev の報告の書式（G1 承認の後）
- #247 の `experiments.csv` の書式のまま、5 型 (a)〜(e) ごとに n・MRR・対照・Δ・95% 区間。型をまとめた列は作らない
- dev の値は最終 2 本の選択に使わない（playbook §4.1）

## 4. 限界
- 比率が分からないので、「どの型も −0.02 より悪くしない」は、どこかの型で大きく良くなっても別の型で少し（0.02 以内）悪くなる変更を通す。隠れテストで悪くなる型が多数を占めれば、全体では負けうる。これは比率が分からない間の割り切りで、#195 B10（型の混ざり方への感度）で最終候補ごとに極端な比率での値を並べて補う
- 点の値の Δ は揺れを含む: `docs/research/adoption-power.md` の se（主の sd、拡大後の n）は C1 0.0082・enveda 0.0084・v3_c2n 0.0108 で、−0.02 はおよそ 2 se の大きさ。本当の差が 0 でも Δ が −0.02 を下回ることがありうる（逆に本当の −0.02 の損が通ることもある。adoption-power.md の R1 の「手放すもの」と同じ性質）。判定の書式は playbook の文のままにし、ここで変えない
