# 装置をまたぐ参照の照合（H2 の根拠と N1 のリスク）

Issue #280（2026-11-27 昼 計画 項目 3）。数え方は数える前に #280 の本文で固定し、補足 2 件（欠けの扱いの直し・不確かさの記述の追加）は本番の集計の前後にコメントで記録した。数はすべて `scripts/research/cross_instrument_sim.py` の出力 `docs/research/cross-instrument-matching.json`（= `outputs/local_eval/cross_instrument_sim.json` の写し）から転記した。

## 結論（先に）

- **隠れテストに近い読み**: train で、**timsTOF の問い合わせ**と、同じ構造・同じ付加イオンの **timsTOF 以外の参照**の entropy 類似度の最大（群ごと = 今の lib_max_sim と同じ「問い合わせ全部 × 参照全部の最大」）は **中央値 0.793**（構造単位のブートストラップ 95% 区間 [0.765, 0.817]）、10% 分位 0.509・90% 分位 0.897、群 119・構造 72
- 同じ構造の **timsTOF どうし**（別のスペクトル。別の衝突エネルギーのものが多いと推定、衝突エネルギーの列は読んでいない＝未確認）は 中央値 0.816 [0.798, 0.848]、10% 0.603・90% 0.910、群 110・構造 61。両方を持つ 83 群で対にすると、差（同じ − 別）の中央値は **+0.002**、別の装置の方が高いか同じ群が 47%。**timsTOF の問い合わせについては、装置をまたいでも最大の類似度はほとんど下がらない**
- 全装置で見ると、生の instrument_type が同じ組の群の最大は 中央値 0.995（10% 0.667）、違う組は 0.742（10% 0.031）。ただし同じ生の値の組には、同じライブラリの重複に近い登録（例: Orbitrap の同じ構造の繰り返し）が多く入るので、0.995 は「同じ測定条件の写し」に近い値で、隠れテストの読みには使えない
- **スキルの記録「装置をまたぐ entropy 類似度の中央値 ≈0.85〜0.90（同じ装置 ≈0.99）」は、train の数とは一部しか合わない**: 生の値は違うが同じ系統の組（例: qTof と QTOF）の群の最大は中央値 0.847 [0.830, 0.865] で記録の下端に近いが、隠れテストに当たる timsTOF → timsTOF 以外は 0.793 で記録より低く、timsTOF どうしも 0.816 で「≈0.99」ではない。下の出典 4 本にも「0.85〜0.90」という中央値は見つからなかった（出典は未確認のまま）。スキルの記録は直す（このカードの後に patch）
- **dev と判定用の 24 集合のすべてで、正解には timsTOF の参照が 1 本も残らない**（隠す規則の後。型 a・e と v3_c1u_t10 は timsTOF 以外の参照だけ、b・c・d と他の判定用は参照なし）。一方 train の構造の 65.5%（275,810 のうち 180,653）は timsTOF の参照しか持たない。したがって「timsTOF の参照との一致」を見分けられる列は、学習でも評価でも**偽物だけが占める領域**を作る。H2 の定義はこれを避ける形にする（下）

## H2 群の定義案（1 つ）

案: **lib_max_sim を「問い合わせと違う系統の装置の参照だけ」で作り直した列に置き換える（足すのではなく置き換える）**。

- 列（3 本）
  - `lib_max_sim_xi`: 候補の参照のうち、装置の系統（`family()`、上の対応表）が問い合わせのスペクトルの系統と違うものだけで計算した、問い合わせ全部 × 参照全部の entropy 類似度の最大（`library.lib_scores` と同じ式・SearchCfg の既定）。L（プール）と Q（PubChem 層、`q_refs`）の両方で同じ規則
  - `has_ref_xi`: その参照が 1 本以上あるか（0/1）
  - `lib_max_sim_xi_sa`: 上のうち、参照の付加イオンが問い合わせと同じものだけでの最大（MS2DeepScore 2.0 で付加イオンは効き、装置の one-hot は効かなかった、が根拠）
  - 相対の列（`_REL`）は `lib_max_sim_xi` に同じ規則で作る
- 置き換え: 今の `lib_max_sim`・`has_ref`・`lib_max_sim_*`（相対）を外し、上の列を入れる。他の列・定数・LightGBM の設定は変えない
- 作り方: `dump_features.py` の `L.lib_scores` に問い合わせ・参照の装置（と付加イオン）を渡す版を足す（参照の読み込みに instrument_type・adduct の 2 列を足す。`_read_rows` の REF_COLS）。問い合わせの装置は holdout / test の `instrument_type`
- NaN の扱い: 今と同じく、参照が無ければ 0.0（`has_ref_xi` = 0）。装置の欠けた参照（NaN・空・nan・N/A）は「違う系統」に数えない（どちらとも言えないので使わない）。欠けた問い合わせの装置は、その問い合わせを使わない（他の問い合わせで計算）。全部欠けた分子は 0
- hide_rule: 集合の規則（`load_refs` / `q_refs`）を当てた**後**の参照に、上の系統の規則を当てる。正解にも偽物にも同じ規則で、正解だけを特別扱いしない
- **偽物だけが占める領域の点検（なぜ置き換えか）**: 24 集合のすべてで正解に timsTOF の参照が残らない（上の補助の数）一方、train の構造の 65.5% は timsTOF の参照しか持たない。「同じ装置（timsTOF）の参照との一致」を見分けられる列（同じ装置の列を足す、今の lib_max_sim を残して xi を足す、など）は、`lib_max_sim > lib_max_sim_xi` が偽物だけに起きる領域を作り、模型は「同じ装置で一致したら偽物」と覚える。隠れテストの正解に train の timsTOF の参照があれば、その正解を押し下げる（スキルの記録にある「lib_sim ≥ 0.92 は常に偽物」の罠と同じ形）。置き換えなら、問い合わせが timsTOF のときは timsTOF の参照をどの候補でも使わないので、この領域ができない（問い合わせが timsTOF 以外の型 b・v3_c2nu_t10 では、外れるのは問い合わせと同じ系統の参照で、timsTOF の参照は xi に入る）。
  - 逆向きのリスク: 型 a・e では置き換えの後も正解の `has_ref_xi` は常に 1、timsTOF の参照しか持たない偽物（train の構造の 65.5%）は 0 になるので、「別系統の参照あり = 正解」の近道は今の `has_ref` より強まるおそれがある。下の点検で `has_ref_xi` を正解 / 偽物ごとに数えて記録する。また、L（プール、train の参照）と Q（PubChem 層、`q_refs`）の両方で同じ規則が効くかは、今回は L の側（train）しか数えていない当てはめの後に次を数える（採否には使わない、記録だけ）:
  - 型ごと・正解 / 偽物ごとの `lib_max_sim_xi`・`has_ref_xi`・`lib_max_sim_xi_sa` の分布（中央値・分位）と、正解が 1 行も無い値の範囲
  - 今の `lib_max_sim` と `lib_max_sim_xi` の差が > 0 の偽物の割合（置き換えで消える信号の大きさ）
  - 反事実: 型 a の正解の行の `lib_max_sim_xi` を timsTOF どうしの群の中央値（0.816、この文書の値）に置いたときの top-1 の変化（スキルの事前に決めた定義の counterfactual sweep と同じ形）
- 失うもの: 隠れテストで正解に timsTOF の参照が本当にあれば、その強い証拠を使えない。ただし今の dev / 判定用の集合ではその場面が 0 回で、模型はその証拠を正しく使うことを学べない（timsTOF の問い合わせでは、今の lib_max_sim の timsTOF 一致は偽物にしか起きないので、それを偽物の印として学んでいると推定。特徴の表では測っていない＝未確認）。train の数では timsTOF をまたいでも最大の類似度はほとんど下がらない（+0.002）ので、置き換えで失う正解の側の信号は小さい見込み（72 構造の数で、未確認の範囲が広い）
