## 候補集合の定義（§2.1・§3.6・S6.2 の文から）

- **質量の窓**（式ではない）。「Candidate lists are the released mass-based lists capped at 256 molecules (mean 255.2 on validation)」（§2.1）、「within the 10-ppm candidate window」（§3.6）。S6.2 にも「original mass-cap 256 candidate pools」
- 問い合わせの分子式は入力にもフィルタにも使わない（§2.1）。正解が候補に無いときに足すことはしない。公式 test は候補の recall 100%（§3 冒頭）
- 構造の単位は RDKit 2025.09.6 の canonical isomeric SMILES、分子ごとの集計は InChIKey の第 1 ブロック（connectivity）。val・test は train と connectivity を共有しない（§2.1）
- 指標は R@1・R@5・R@20・MRR。スペクトルごと（query-weighted）と connectivity ごと（connectivity-balanced）の両方
- 10 ppm の窓の作り方そのものは MassSpecGym の原論文 [2] の定義で、ここでは読み直していない

## 要点（読んだ範囲で、数字は本文の値）

1. **2 段の役割の分離**: 2 段目は 1 段目の shortlist（上位 20）を並べ替えるだけなので R@20 は変わらない（72.62%）。最終系は R@1 31.05%（1 段目の ensemble 21.01% から +10.05 [8.65, 11.51]）。MSAlign の ensemble より R@1 は高いが R@20 は 3.98 点低い。「R@1 だけを報告すると shortlist の不足が隠れる」（§3.1、§4）
2. **スペクトルを使わない精度**: 学習平均のスペクトルで R@1 13.75%、スペクトルを見ない candidate-only の基準線で 7.87%（乱数 0.40%）。候補のリスト自体が事前の情報を持つ（§3.3）。同じ付加イオン・前駆体質量の別の分子のスペクトルに替えると最終系は約 9 点（connectivity-balanced で約 15 点）下がる
3. **誤りは分子に固まる**: 4 本以上のスペクトルを持つ 762 connectivity で、1 段目の ICC(1) 0.74、全スペクトルで誤る分子 64%（並べ替えの帰無で 19%）（§3.4、Table 4）
4. **学習の近傍の近さと到達**: 近さ = SCCF の生の特徴（Morgan r2 count・atom pair・path・MACCS、ブロックごとに L2 正規化）の cosine で、学習の正解 25,046 分子のうち最も近いものとの値（§2.6、S4.1）。公式 test で 1 段目の R@20 は近さ 0.60〜0.70 で 46.5%、0.80〜0.90 で 93.1%（観察、connectivity 単位の Spearman 0.38）（Fig. 4b、Table S11）。ただし近さで説明できる分子間の分散は 9〜21% だけ
5. **介入（因果）**: val の 200 分子（近さ ≥ 0.90 の分子から抽出）について、cosine 0.80 以内の学習分子をすべて外して（17,504 スペクトル、1,219 connectivity）1 段目を学び直すと、同じ数の遠い分子を外した場合と比べて R@20 が 91.0% → 62.0%、R@1 が 29.6% → 4.9%（Table S25: 全学習 93.14%、targeted 62.04%、random 91.02%）。近傍に触れなかった 2,691 分子の変化は 1 点未満。差の差 −29.9 点 [−42.5, −19.5]。作者自身が「最初からよく覆われた分子と 1 段目だけの結論」と限定している
6. **前駆体の質量**: 10 ppm の窓の中でも質量の誤差の事前分布がどの手法にも情報を足す（§3.6、表は読んでいない）
7. 学習した peak–fragment の類似度は、定数の coverage を上回らなかった（§4。§3.7 の表は読んでいない）

## こちらへの当てはめ: v3 の正解の学習近傍の近さ別の値（#232 の定義どおり 1 回）

定義（#232 の本文で値を見る前に固定）: 学習側 = `train_structs.parquet` のうち sid が `data/ext/foldsafe/split.parquet` に無い 220,443 行（fold-0 の FPNet の学習側）。近さ = RDKit（.venv の 2026.09.1）Morgan 半径 2・2048 bit のビット指紋の Tanimoto の、学習側全体での最大値。区分 < 0.5 / [0.5, 0.8) / ≥ 0.8。値は対照 score,prior,frag の rr の平均（MRR@25）、CI は区分の中で分子を復元抽出する percentile bootstrap 2000 回（各セル seed 0）。

### 読み方（記述だけ）

- v3_c1u・enveda_v1u・v3_c2 は、近さ ≥ 0.8 の正解が 1 割未満で、ほとんどが 0.5〜0.8 にある。identity-disjoint の fold で作った集合なので、論文の「近い学習の近傍がある分子」が多くを占める状態ではない（ただし尺度が違う: 論文は SCCF の count 特徴の cosine、こちらは Morgan r2 ビットの Tanimoto。0.8 という値を論文と直接比べない）
- v3_c1u と enveda_v1u では ≥ 0.8 の MRR が 0.5〜0.8 より低く（0.839 vs 0.890、0.787 vs 0.865）、近いほど高いという向きは見えない。CI は重なっている
- v3_c2nu だけは近いほど MRR が高い向き（0.565 → 0.617 → 0.687）だが、CI は重なる。≥ 0.8 の 35% は上に書いた脂質の同族体が多く、ビット指紋の近さが鎖長の違いを拾わないことを含む
- B8 への読み: 論文の介入の結論（近い学習の近傍が 1 段目の到達を因果的に支える）は、こちらでは「プールに入るか（到達）」ではなく、プールの中の並べ替え（対照 score,prior,frag）の MRR で見ている。この表は到達の分解ではない。v3_c2 型（プールの外）の到達を近さ別に見るなら、PubChem の層の窓の中の正解の有無を近さ別に数える必要があり、今回はしていない
- 隠れ test の正解の近さの分布は分からない（見える test は train の写し）。この表から「v3 は甘い／辛い」は言えない。言えるのは「v3 の 3 集合は近さ ≥ 0.8 が 1 割未満で、近さ別の MRR に単調な差は見えない」まで
