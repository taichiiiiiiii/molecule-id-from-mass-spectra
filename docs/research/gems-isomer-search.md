## 1. GEMS（出典 1）

### 何をするか（確認、§3〜§4）
- 分子式が既知の設定。分子式と MS/MS から、MIST（凍結）で 4,096 ビットの Morgan 指紋（半径 2）の確率 q を 1 回だけ予測する
- 初期の候補（start）: PubChem の同じ分子式の分子を、Bernoulli の対数尤度 s(m;q) = Σ[x_i log q̃_i + (1−x_i) log(1−q̃_i)]（q̃ は 1e-7〜1−1e-7 に切る）で並べ、InChIKey14 ごとに 1 つにして上位 K=5 を取る。「target-excluded」評価では、正解の InChIKey14 を先に除く。つまり**正解を当てるには必ず 1 回以上の編集が要る**
- 編集: 分子式と各原子の結合次数の合計を保つ「2-switch」（2 本の結合の 1 単位ずつを付け替える Type-A と、水素を 1 つ動かす Type-B。ケト・エノールの変換は Type-B の 1 回）
- 学習した方策（Graphormer 型の分子の符号器 + 指紋のトークン 128 個）が、すべての有効な編集を 1 回の順伝播で採点し、ビーム探索（P=B=16、深さ D=3）で進む。1 つの start あたり最大 1+B·D の状態を残し、5 start で最大 245 状態
- 最後の並べ: R(m;q) = s(m;q) + λ·log(1+c(m))。c(m) は m に届いた start の数（合意）。λ=16 は MassSpecGym の検証の Hit@1 で選んだ（確認、§4.6・J.2）

### 候補集合の定義（確認）
- 評価の候補は「探索が残した状態の集合」（start と各深さのビームの状態、最大 245、InChIKey14 で重複除去）。PubChem の同じ式の全分子ではない
- 「reach」= 残した集合に正解の InChIKey14 があるクエリの割合。Hit@k の上限（F.1）
- 評価: NPLIB1 の 803 スペクトル（[M+H]+ だけ、FRIGID と同じ分割）、MassSpecGym の test 17,556（[M+H]+ 14,066、[M+Na]+ 3,490）。start が無いクエリ（NPLIB1 17、MSG 200）も失敗として分母に入る
- 照合は InChIKey14（立体なし）

### 異性体の区別の数値（確認）
- 本体（表 1、表 15 の λ=16）: Hit@1 / Hit@10 / reach = NPLIB1 29.64 / 50.81 / 57.78 %、MSG 30.22 / 41.33 / 46.88 %
- **日報 §4-5 の「正確な指紋なら Hit@1 29.64% → 56.66%」の意味（§5.6、表 15）**: 探索（MIST で進む）が残した候補集合と合意の数を固定したまま、**並べに使う指紋だけ**を正解そのものの指紋 x(t) に替えた値。集合は変わらないので reach 57.78% は同じで、56.66% はその上限 57.78% のほぼ全部。MSG は 30.22 → 45.12%（reach 46.88%）
  - 件数に直すと（こちらの計算、小数の丸めのため ±1 件）: NPLIB1 は reach 464 件のうち 455 件で正解が 1 位、届いたのに 1 位にならないのは 9 件。合意の項を外す（λ=0）と 446 件で 18 件
  - 正解の指紋を q にした s(m;q) は、1 ビットの違いごとに約 ln((1−1e-7)/1e-7) ≈ 16.1 下がる「x(m) と x(t) のハミング距離」の単調な関数（こちらの計算）。λ=16 では合意の項の差（最大 16·ln(6/2) ≈ 17.6）がビット 1 つ分の差を上回れるので、ハミング距離 1 で票の多い候補が正解を上回ることがあり得る
  - 届いたのに正解が 1 位でない件（λ=0 で 18 件、λ=16 で 9 件）の原因は、(1) 正解と指紋が全く同じ別の候補（同点。同点の扱いは本文に無い）、(2) 正解の InChIKey14 グループの代表（グループの中で点が最高の候補、§4.6）が正解とは別の互変異性体などで、指紋が x(t) と違う（探索の重複除去と合意は立体なしの正準 SMILES 単位で互変異性体を分け、評価は InChIKey14 単位、表 2）、(3) λ=16 では合意の項、のいずれかで、内訳は**未確認**。(2) があり得る手がかりとして、正確な指紋・λ=0 でも H@10 57.66%（463 件）が reach 57.78%（464 件）より 1 件少なく、正解が上位 10 にも入らないクエリがある（表 15）
  - 読み: **「指紋が正確なら、届いた候補の中ではほとんどの場合、正解が 1 位」**（464 件中 446〜455 件）。Morgan 4,096 ビット（半径 2）で区別できない異性体を持つクエリの数は出せない。同点で正解が負けた件は多くても 18 件（λ=0）だが、同点でも正解が先に来た件は表に現れないので、区別できない異性体を持つ件数そのものは上限も下限も分からない（**未確認**）。外れの大部分は指紋の予測の誤り（MIST の誤差）から来る、と著者は結論する（§5.6「Fingerprint prediction error thus limits both recovery and final ranking」）
- 進む指紋も正解に替えると: Hit@1 68.99%、reach 72.85%（NPLIB1）。MSG 53.09%、56.07%
- 正解に近い start を除く感度（表 8）: Tanimoto ≥ 0.7 の start も除くと NPLIB1 27.90%、MSG 23.93%。正解から 1 編集の start をすべて除くと 25.53%、22.44%
- 編集の深さ（H.2）: target-excluded で D1/D2/D3 の Hit@1 = 27.02 / 29.39 / 29.64 %（NPLIB1）。**当たりの大部分は 1 回の編集で届く**（PubChem の start に正解の 1 編集隣が多くある、と読める。推測。表 9 の件数は読んでいない）
- 学習なしの「Enumerate & Score」（1 編集隣をすべて作って s(m;q) で上位 B を残す、§5.4・表 6）: B=4 で NPLIB1 Hit@1 26.03%、reach 54.17%（GEMS は 29.64%、57.78%）。重みがランダムの方策は 4.61 ± 2.90%
- ICEBERG の予測スペクトルで上位 10 を並べ替えると +2.24 [0.62, 3.96] pt（NPLIB1）、+1.38 [0.40, 2.80] pt（MSG）（表 16）。重み β と類似度の種類は検証の Hit@1 で選んだ（確認、J.3）

### 学習データ（確認、§4.4・付録 B・D.1）
- 方策の事前学習: PubChem の同じ式の分子の組（1〜2 編集）、正解の指紋を入力（スペクトル不要）。採掘した組 986,681,148、うち 1.25 億を抽出。両ベンチの val・test の構造はあらかじめ除く（B.1）
- 微調整: 各ベンチの train の正解と、同じ式の PubChem 分子（1〜3 編集）。指紋は MIST が train のスペクトルから予測したもの
- MIST の符号器: 「released FRIGID MIST encoders」の `mist_canopus.pt`（NPLIB1）と `mist_msg.pt`（MSG）（D.1）
- 注意（出典 5、確認）: FRIGID の README は今、「前の版の MassSpecGym 用 MIST の学習は、テストの分子の分子式に合う・似る PubChem 分子の合成スペクトルを使っており、テストの構造そのものは除いたがテストの情報を使っていた」と書き、符号器を差し替えて結果を出し直したとしている。GEMS が使った `mist_msg.pt` がこの差し替え前のものか、GEMS の MSG の数値がその影響を受けるかは**未確認**（GEMS の投稿 10-16、FRIGID の最終 push 10-21。README の注記がいつ入ったかは確かめていない）。正確な指紋の実験（並べだけを替える）は MIST の誤差を取り除く操作なので、「届いた中ではほぼ 1 位」という結論はこの影響を受けにくいと読む（推測）

## 2. MassSpecGym の検索と bonus（出典 2）

### 候補集合の定義（確認、§3.2・§3.3）
- 通常の検索: 正解と同じ質量（許容誤差内）の分子。1 スペクトルあたり最大 256。(i) 生物・環境由来の 100 万分子 → (ii) 400 万分子 → (iii) PubChem 1.18 億の順に、256 に達するまで抽出
- **bonus（分子式が既知）**: 同じ手順で、候補を**同じ分子式**の分子に限る。同じ式の異性体の並べ替えのベンチにあたる
- 分割: MCES 距離 10 未満の分子が別の fold に入らないようにまとめた（構造で分けた分割）

### 数値（確認、表 5）
- 通常（質量）: MIST Hit@1 14.64%、@5 34.87%、@20 59.15%。ランダム 0.37%
- **bonus（同じ式）**: MIST Hit@1 **9.57%**、@5 22.11%、@20 41.12%。ランダム 3.06%（候補が少ないので高い）。Fingerprint FFN 5.09%、DeepSets + Fourier 6.56%
- 読み: 同じ式に絞ると候補は減るのに MIST の Hit@1 は 14.64 → 9.57% に下がる。質量の窓で並べていた勝ちの一部は「式の違う候補を落とす」ことから来ており、残る同じ式の異性体の区別はより難しい、と読める（推測）

## 4. MIST の同じ式の検索（出典 4）

### 候補集合の定義（確認、§9.6）
- PubChem（2022 年 4 月版）から、スペクトルの分子式に一致する**すべての異性体**を、予測指紋との cosine で並べる。同点は楽観的に最小の順位を取る

### 数値（確認、表 S4。CANOPUS の GNPS 部分集合 = [M+H]+ 8,030 スペクトル・7,131 化合物、構造で分けた 3 分割の結果をまとめたもの）
- MIST の指紋だけ: Top-1 29.37%、Top-20 72.23%
- MIST の対照学習 + 指紋（重み λ_r=0.3、1 つの fold で手で決めた、と本文）: Top-1 30.70%、Top-20 75.71%
- 表 S2（5 モデルのアンサンブル「MIST (5x)」、GNPS・MoNA・NIST20 の [M+H]+ 31,145 スペクトルの CSI:FingerID との比較用の集合）: 対照学習ありで Top-1 37.39%、cosine（指紋だけ）31.70%。単体の MIST は 34.45%、29.72%。CSI:FingerID は cosine 38.24%、Bayes 43.00%（NIST は競技では使えない、750330）
- 読み: 「PubChem の同じ式の全異性体」の中で、予測指紋だけで 1 位にできるのは約 3 割。GEMS の 29.64%（正解を PubChem から除いた上で編集で作る、最大 245 候補）と数は近いが、候補集合（PubChem 2022 の全異性体と、編集で作った集合）も分割（3 つの構造分割と、FRIGID の分割）も違うので、直接は比べられない

## この競技で使えるか

- 規則: 外部データは「オープンで誰でも手に入る」もの（非商用ライセンスも可）。NIST とその派生物（重みを含む）は不可（750330、確認）。MassSpecGym と MIST の重みは可（757307、確認）。再現できない中間物を読む解は再現性なし（756893、`docs/research/lineage-reproducibility.md`）
- **GEMS そのもの**: 今は**使えない**。コードと学習済みの方策が未公開で、提出に入れても再現性の条件を満たせない。公開されたら、方策の学習データ（PubChem と、各ベンチの train。NPLIB1 用の MIST は CANOPUS の GNPS 部分集合）に NIST が入るかを確かめてから判断する（今は**未確認**）
- **自前で作る場合**: 2-switch の編集と Enumerate & Score（学習なし）は本文の記述から自前の RDKit のコードで作れる（推測。作っていない）。ただし過去の自前の編集の生成（スキルの記録、`analog_edit_reach.py`）は、リーク無しの fold-0 のロジットでは「届く」が「1 位にできない」ため、損益分岐の割合が 65〜83% で不採用だった。GEMS の §5.6 も、外れは「届かない」より「並べで負ける」ことが大きいと示す。**候補を増やす前に、今の採点の式が並べで負ける理由を測るのが先**
- **MassSpecGym の bonus の候補集合**: 同じ式の異性体の並べのベンチとして使える（MIT、757307 で可）。ただし v3_c2n の正解の 58.5% が MSG にある（#66）ので、自前の部品の学習に MSG を使うと v3 の 4 集合での測定に制約がつく
- **PubChem の順の偏り**: この競技の prior が既に同じ種類の偏りを使っている。新しい部品にはならない

## v3_c1 で測る案（1 つ。定数の掃引ではない）

### 案: score 段で正解が 1 位の候補に負ける差を消すのに要る「指紋の予測の誤りの量」を数える（GEMS §5.6 の介入を score 段に移したもの）

GEMS §5.6 は「並べの指紋だけを正解に替えると、届いた候補の中ではほとんど正解が 1 位」を示した。縮小版でこれをそのまま行うと、答えはほぼ前もって分かる。#118 によると v3_c1 の (c) 44 件で、1 位の候補と正解の Morgan（半径 2・2,048 ビット）の Tanimoto の中央値は 0.491、0.85 以上は 0 件。指紋が正解と全く同じ別の候補はほぼ無いと予想でき、「正解の指紋なら直る」はほぼ全件で成り立つ（予想。測るのは下の 2）。さらに #118 には、(c) 44 件のうち score 段だけなら正解が 1 位だった件が 4 件ある（後段の prior・frag で落ちた）。そこで、前もって分からない量として、**score 段の 1 位の候補との 1 対 1 の差を消すのに、予測の誤りを何ビット分取り除けばよいか**を数える。これで「少数のビット（特定の部分構造）の誤りが効いている」のか「多くのビットに薄く広がった誤り」なのかが分かり、次の自前部品を選べる。前者なら部分構造を直接見る証拠（断片の説明 fragnn、#120）、後者なら指紋の予測そのものの改善（自前の指紋モデルの学習）が向く。

- 集合: v3_c1 の 200 分子（正解がプールに残る型）。候補は今の score 段と同じ（`scripts/local_eval/run.py` の `visible_window`、±10 ppm、`drop_keys` を除く。重複除去は run.py と同じ pool の key）。正解かどうかの判定は #118 と同じ `mrr25.to_key`（互変異性体を正準化してから InChIKey14）。正解 t は「窓の中で to_key が正解と一致する候補のうち、score 段（元の z）の点が最高のもの」と定め、x(t) と fp(t) はその候補の指紋を使う（窓に正解キーの候補が複数ある件数と、t の指紋が truth.csv の SMILES の指紋と違う件数も別に出す）。v3_c2 は正解をプールから見えなくする型なので対象外と書く
- 指紋: 今の score 段と同じ `casmi.chem.raw_fingerprint`（0/1、確認: `casmi/chem.py` の `FP_BLOCKS`）から `fp_bits.npy` の 10,226 ビットを選んだもの。ブロックごとに残るビット数は ECFP4 1,464/4,096、ECFP6 3,278/4,096、FCFP4 792/2,048、RDKit 2,048/2,048、原子対 1,678/2,048、ねじれ 827/2,048、MACCS 139/167（こちらで数えた）。ECFP4 の 64% が落ちているので、GEMS の Morgan 4,096 を含む上位集合ではない
- 出すもの:
  1. **段ごとの分け方**（v3_c1 の score+prior+frag の 1 位の外れ 49 件を、同じコードで出し直してから）: (i) score 段（元のロジット z）で正解が 1 位でない、(ii) score 段では 1 位なのに prior・frag で落ちた、(iii) 正解の指紋 z* = 2·x(t) − 1 で並べても正解が 1 位にならない（指紋が同じ別の候補がある）。z* での並べは fp·z* = |x(t)| − ハミング距離(fp, x(t)) で、GEMS の正解の指紋での Bernoulli の並べ（λ=0）と同じ順。#118 からの予想は (ii) = 4 前後（(c) の分）、(iii) ≈ 0
  2. **直すのに要るビットの数 k**（主な量）: (i) の各分子で、score 段の 1 位の候補 w と正解 t の差 m = (fp(w) − fp(t))·z > 0 を、ビットごとの寄与 c_i = (fp_i(w) − fp_i(t))·z_i に分ける。c_i > 0 のビット（w を有利にしている予測）を寄与の大きい順に 1 つずつ z_i = 0 にして（その予測を取り除いて）、m ≤ 0 になるまでのビット数を k とする。正の寄与をすべて取り除けば m ≤ 0 になるので k は必ず決まる（はじめから m = 0 の同点なら k = 0）。定数は使わない。k は w との 1 対 1 の差を消す数で、取り除いた後に正解が 1 位になるとは限らない（z_i = 0 はほかの候補の点も変える）。参考として、k ビットを取り除いた後の z での正解の順位も出す。あわせて、w と t で違うビットの数と、c_i > 0 のビットの数を出す
  3. 参考: 200 分子全体で z* で並べたときの MRR@25 と Hit@1（同点は悲観・楽観の 2 通り）、正解と指紋が全く同じ別の候補がある分子の数（同じ分子式とそれ以外に分けて）
  4. 配線の確認: 同じコードで、元の z の score 段が `result_score.json` の MRR 0.8395、score+prior+frag が 0.8535 を同じ値で出し、#118 の外れ 49 = (a) 3 ＋ (b) 2 ＋ (c) 44 を再現すること。どれかが違えば測りは無効
- 読み方（前もって決める。採否には使わない、定数も選ばない。帯は (i) の分子の k の中央値で固定）:
  - k の中央値 ≤ 5 → 「少数のビットの誤り」が主。部分構造を直接見る証拠（fragnn、#120）を次の自前部品で先にする
  - k の中央値 ≥ 50 → 「広く薄い誤り」が主。指紋の予測そのものの改善（自前の指紋モデルの学習。v3 で測るには fold-safe に学習する）を先にする
  - その間は「両方を残す」とし、どちらも優先しない。(iii) が 5 件以上なら、帯とは別に「この指紋では見分けられない外れ」として件数を報告する。どの場合も、この結果で定数・しきい値を動かさない
- 費用の見込み: score 段は v3_c1 で 29.3 秒（`result_score.json`）、score+prior+frag は 37.1 秒。k の計算は分子ごとに 10,226 次元の並べ替え 1 回なので、合わせて CPU で数分以内と見込む（測っていない）。メモリは score 段と同じ。GPU 0、提出 0
- 進め方: 別の Issue で事前登録（この案の出すもの・読み方をそのまま書く）→ 独立レビュー → `scripts/research/` に置いて測る

## 結論

- 日報の「29.64% → 56.66%」は、**探索が残した最大 245 の候補の中で、並べの指紋だけを正解に替えた**値で、PubChem の同じ式の全体での数ではない。上限は reach（57.78%）で、56.66% はそのほぼ全部。「届いた候補の中では、4,096 ビット Morgan の正確な指紋があればほとんどの場合 1 位」= 外れの主因は指紋の予測の誤り、というのが GEMS の結論（確認）
- 同じ式の異性体の並べのベンチの数（Hit@1）: MSG bonus の MIST 9.57%（最大 256 の同じ式の候補）、MIST の PubChem の全異性体 29.37〜30.70%（CANOPUS の GNPS 部分集合）、GEMS 29.64%（正解を除いて編集で作る）。候補集合と分割がそれぞれ違うので、互いに直接は比べられない。スペクトルを見ない PubChem の順が MSG bonus で 49.98%
- GEMS はコード未公開で今は使えない。編集の生成は過去に自前で試して不採用。縮小版では「正解の指紋なら直る」はほぼ前もって分かる（#118 の Tanimoto）ので、次の一手は、score 段の外れを直すのに要る予測の誤りの量（上の案の k）を数えて、fragnn と指紋モデルの学習のどちらを先にするかを決める
