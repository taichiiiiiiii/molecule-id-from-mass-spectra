## 1. GEMS（出典 1）

### 何をするか（確認、§3〜§4）
- 分子式が既知の設定。分子式と MS/MS から、MIST（凍結）で 4,096 ビットの Morgan 指紋（半径 2）の確率 q を 1 回だけ予測する
- 初期の候補（start）: PubChem の同じ分子式の分子を、Bernoulli の対数尤度 s(m;q) = Σ[x_i log q̃_i + (1−x_i) log(1−q̃_i)]（q̃ は 1e-7〜1−1e-7 に切る）で並べ、InChIKey14 ごとに 1 つにして上位 K=5 を取る。「target-excluded」評価では、正解の InChIKey14 を先に除く。つまり**正解を当てるには必ず 1 回以上の編集が要る**
- 編集: 分子式と各原子の結合次数の合計を保つ「2-switch」（2 本の結合の 1 単位ずつを付け替える Type-A と、水素を 1 つ動かす Type-B。ケト・エノールの変換は Type-B の 1 回）
- 学習した方策（Graphormer 型の分子の符号器 + 指紋のトークン 128 個）が、すべての有効な編集を 1 回の順伝播で採点し、ビーム探索（P=B=16、深さ D=3）で進む。1 つの start あたり最大 1+B·D の状態を残し、5 start で最大 245 状態
- 最後の並べ: R(m;q) = s(m;q) + λ·log(1+c(m))。c(m) は m に届いた start の数（合意）。λ=16 は MassSpecGym の検証の Hit@1 で選んだ（確認、§4.6・J.2）

### 候補集合の定義（確認）
- 評価の候補は「探索が残した状態の集合」（start と各深さのビームの状態、最大 245、InChIKey14 で重複除去）。PubChem の同じ式の全分子ではない
- 「reach」= 残した集合に正解の InChIKey14 があるクエリの割合。Hit@k の上限（F.1）
- 評価: NPLIB1 の 803 スペクトル（[M+H]+ だけ、FRIGID と同じ分割）、MassSpecGym の test 17,556（[M+H]+ 14,066、[M+Na]+ 3,490）。start が無いクエリ（NPLIB1 17、MSG 200）も失敗として分母に入る
- 照合は InChIKey14（立体なし）

### 異性体の区別の数値（確認）
- 本体（表 1、表 15 の λ=16）: Hit@1 / Hit@10 / reach = NPLIB1 29.64 / 50.81 / 57.78 %、MSG 30.22 / 41.33 / 46.88 %
- **日報 §4-5 の「正確な指紋なら Hit@1 29.64% → 56.66%」の意味（§5.6、表 15）**: 探索（MIST で進む）が残した候補集合と合意の数を固定したまま、**並べに使う指紋だけ**を正解そのものの指紋 x(t) に替えた値。集合は変わらないので reach 57.78% は同じで、56.66% はその上限 57.78% のほぼ全部。MSG は 30.22 → 45.12%（reach 46.88%）
  - 件数に直すと（こちらの計算、小数の丸めのため ±1 件）: NPLIB1 は reach 464 件のうち 455 件で正解が 1 位、届いたのに 1 位にならないのは 9 件。合意の項を外す（λ=0）と 446 件で 18 件
  - 同点（正解と全ビットが同じ指紋の別の異性体）をどう扱ったかは本文に書かれていない（**未確認**）。正解の指紋を q にした s(m;q) は「x(m) と x(t) のハミング距離」の単調な関数なので、正解より上に来られるのは指紋が全く同じ別の構造だけ。上の 9〜18 件はその同点か合意の項による（どちらかは**未確認**）
  - 読み: **「指紋が正確なら、届いた候補の中ではほぼ必ず正解が 1 位」= この候補集合では、4,096 ビット Morgan（半径 2）で区別できない異性体はまれ**（NPLIB1 で多くて 18/803 = 2.2%）。外れの大部分は指紋の予測の誤り（MIST の誤差）から来る、と著者は結論する（§5.6「Fingerprint prediction error thus limits both recovery and final ranking」）
- 進む指紋も正解に替えると: Hit@1 68.99%、reach 72.85%（NPLIB1）。MSG 53.09%、56.07%
- 正解に近い start を除く感度（表 8）: Tanimoto ≥ 0.7 の start も除くと NPLIB1 27.90%、MSG 23.93%。正解から 1 編集の start をすべて除くと 25.53%、22.44%
- 編集の深さ（H.2）: target-excluded で D1/D2/D3 の Hit@1 = 27.02 / 29.39 / 29.64 %（NPLIB1）。**当たりの大部分は 1 回の編集で届く**（PubChem に正解の 1 編集隣が多くある）
- 学習なしの「Enumerate & Score」（1 編集隣をすべて作って s(m;q) で上位 B を残す、§5.4・表 6）: B=4 で NPLIB1 Hit@1 26.03%、reach 54.17%（GEMS は 29.64%、57.78%）。重みがランダムの方策は 4.61 ± 2.90%
- ICEBERG の予測スペクトルで上位 10 を並べ替えると +2.24 [0.62, 3.96] pt（NPLIB1）、+1.38 [0.40, 2.80] pt（MSG）（表 16）。重み β と類似度の種類は検証の Hit@1 で選んだ（確認、J.3）

### 学習データ（確認、§4.4・付録 B・D.1）
- 方策の事前学習: PubChem の同じ式の分子の組（1〜2 編集）、正解の指紋を入力（スペクトル不要）。採掘した組 986,681,148、うち 1.25 億を抽出。両ベンチの val・test の構造はあらかじめ除く（B.1）
- 微調整: 各ベンチの train の正解と、同じ式の PubChem 分子（1〜3 編集）。指紋は MIST が train のスペクトルから予測したもの
- MIST の符号器: 「released FRIGID MIST encoders」の `mist_canopus.pt`（NPLIB1）と `mist_msg.pt`（MSG）（D.1）
- 注意（出典 5、確認）: FRIGID の README は今、「前の版の MassSpecGym 用 MIST の学習は、テストの分子の分子式に合う・似る PubChem 分子の合成スペクトルを使っており、テストの構造そのものは除いたがテストの情報を使っていた」と書き、符号器を差し替えて結果を出し直したとしている。GEMS が使った `mist_msg.pt` がこの差し替え前のものか、GEMS の MSG の数値がその影響を受けるかは**未確認**（GEMS の投稿 10-16、FRIGID の最終 push 10-21。README の注記がいつ入ったかは確かめていない）。正確な指紋の実験（並べだけを替える）は MIST の誤差を取り除く操作なので、「届いた中ではほぼ 1 位」という結論はこの影響を受けにくいと読む（推測）

## 2. MassSpecGym の検索と bonus（出典 2）

### 候補集合の定義（確認、§3.2・§3.3）
- 通常の検索: 正解と同じ質量（許容誤差内）の分子。1 スペクトルあたり最大 256。(i) 生物・環境由来の 100 万分子 → (ii) 400 万分子 → (iii) PubChem 1.18 億の順に、256 に達するまで抽出
- **bonus（分子式が既知）**: 同じ手順で、候補を**同じ分子式**の分子に限る。同じ式の異性体の並べ替えのベンチにあたる
- 分割: MCES 距離 10 未満の分子が別の fold に入らないようにまとめた（構造で分けた分割）

### 数値（確認、表 5）
- 通常（質量）: MIST Hit@1 14.64%、@5 34.87%、@20 59.15%。ランダム 0.37%
- **bonus（同じ式）**: MIST Hit@1 **9.57%**、@5 22.11%、@20 41.12%。ランダム 3.06%（候補が少ないので高い）。Fingerprint FFN 5.09%、DeepSets + Fourier 6.56%
- 読み: 同じ式に絞ると候補は減るのに MIST の Hit@1 は 14.64 → 9.57% に下がる。質量の窓で並べていた勝ちの一部は「式の違う候補を落とす」ことから来ており、残る同じ式の異性体の区別はより難しい、と読める（推測）

## 4. MIST の同じ式の検索（出典 4）

### 候補集合の定義（確認、§9.6）
- PubChem（2022 年 4 月版）から、スペクトルの分子式に一致する**すべての異性体**を、予測指紋との cosine で並べる。同点は楽観的に最小の順位を取る

### 数値（確認、表 S4。CANOPUS の GNPS 部分集合 = [M+H]+ 8,030 スペクトル・7,131 化合物、構造で分けた 3 分割の結果をまとめたもの）

- MIST の対照学習 + 指紋（重み λ_r=0.3、1 つの fold で手で決めた、と本文）: Top-1 30.70%、Top-20 75.71%
- 本文: NIST の版で対照学習ありの MIST は Top-1 37.39%、指紋だけ 31.70%（NIST は競技では使えない、750330）
- 読み: 「PubChem の同じ式の全異性体」の中で、予測指紋だけで 1 位にできるのは約 3 割。GEMS の 29.64%（正解を PubChem から除いた上で編集で作る）はこれと同じ水準

## この競技で使えるか

- 規則: 外部データは「オープンで誰でも手に入る」もの（非商用ライセンスも可）。NIST とその派生物（重みを含む）は不可（750330、確認）。MassSpecGym と MIST の重みは可（757307、確認）。再現できない中間物を読む解は再現性なし（756893、`docs/research/lineage-reproducibility.md`）
- **GEMS そのもの**: 今は**使えない**。コードと学習済みの方策が未公開で、提出に入れても再現性の条件を満たせない。公開されたら、方策の学習データ（PubChem と、各ベンチの train。NPLIB1 用の MIST は CANOPUS の GNPS 部分集合）に NIST が入るかを確かめてから判断する（今は**未確認**）
- **自前で作る場合**: 2-switch の編集と Enumerate & Score（学習なし）は本文の記述から自前の RDKit のコードで作れる（推測。作っていない）。ただし過去の自前の編集の生成（スキルの記録、`analog_edit_reach.py`）は、リーク無しの fold-0 のロジットでは「届く」が「1 位にできない」ため、損益分岐の割合が 65〜83% で不採用だった。GEMS の §5.6 も、外れは「届かない」より「並べで負ける」ことが大きいと示す。**候補を増やす前に、今の採点の式が並べで負ける理由を測るのが先**
- **MassSpecGym の bonus の候補集合**: 同じ式の異性体の並べのベンチとして使える（MIT、757307 で可）。ただし v3_c2n の正解の 58.5% が MSG にある（#66）ので、自前の部品の学習に MSG を使うと v3 の 4 集合での測定に制約がつく
- **PubChem の順の偏り**: この競技の prior が既に同じ種類の偏りを使っている。新しい部品にはならない

## v3_c1 で測る案（1 つ。定数の掃引ではない）

### 案: 「正解の指紋で並べたときの上限」を score 段の式で数え、#118 の (c) 44 件を「指紋で見分けられる外れ」と「指紋では見分けられない外れ」に分ける

GEMS §5.6 の介入（集合を固定して、並べの指紋だけ正解に替える）を、縮小版の score 段にそのまま移す。

- 集合: v3_c1 の 200 分子。候補は今の score 段と同じ（`scripts/local_eval/run.py` の `visible_window`、±10 ppm、`drop_keys` を除く。順位は出力段と同じく InChIKey14 で重複除去した後で数える）。v3_c1 は正解がプールに残る型なので、この上限が定義できる。v3_c2 は正解をプールから見えなくする型なので、この段の上限は定義できない（報告には「対象外」と書く）
- 指紋: 今の score 段と同じ `casmi.chem.raw_fingerprint`（0/1 の ECFP4 4096・ECFP6 4096・FCFP4・RDKit・原子対・トポロジカルねじれ各 2048・MACCS 167 をつないだもの、確認: `casmi/chem.py` の `FP_BLOCKS`）から `fp_bits.npy` の 10,226 ビットを選んだもの。GEMS の Morgan 4,096 ビットより種類が多いので、同点はさらに少ないと見込む（推測。測るのはこの案）
- 介入: ロジット z を z* = 2·x(t) − 1（x(t) は正解の指紋のビット）に替えるだけ。fp·z* = |x(t)| − ハミング距離(fp, x(t)) なので、GEMS の正解の指紋での Bernoulli の並べと同じ順になる。選ぶ定数は無い
- 出すもの（すべて 200 分子が分母）:
  1. 上限の MRR@25 と Hit@1。同点（指紋が正解と全く同じ別の候補）は、悲観（正解を同点の最後）と楽観（最初）の 2 通りで出す
  2. 正解と指紋が全く同じ別の候補がある分子の数（同じ分子式とそれ以外に分けて）
  3. #118 の (c) 44 件それぞれについて、score+prior+frag の 1 位の候補の指紋が正解と全く同じか違うか。違えば「指紋の予測の誤り」、同じなら「この指紋では見分けられない」
  4. 配線の確認: z* でなく元の fold-0 のロジット z を入れた同じコードが、`result_score.json` の MRR 0.8395 を同じ値で出すこと（違えば測りは無効）
- 読み方（前もって決める。採否には使わない、定数も選ばない。帯は 44 件の数で固定）:
  - (c) 44 件のうち 1 位の候補の指紋が正解と違うものが 30 件以上（2/3 以上）→ GEMS と同じく「指紋の予測の誤り」が主因。次の自前部品は指紋の予測そのものの改善（自前の指紋モデルの学習。v3 で測るには fold-safe に学習する）を先にする
  - 指紋が正解と全く同じものが 22 件以上（半分以上）→ この指紋では何をしても直らない分が主。断片の説明（fragnn、#120）か順方向のスペクトルのような別の証拠を先にする
  - その間（指紋が同じものが 15〜21 件）は「両方を残す」とし、どちらも優先しない。どの帯でも、この結果で定数・しきい値を動かさない
