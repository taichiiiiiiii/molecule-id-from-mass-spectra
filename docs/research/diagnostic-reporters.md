## 1. 文献の要点

### 1.1 diagnostic reporters（出典 1、要約だけ）
- 問い（主張）: 分子の網（MN）で、どの断片イオン・中性損失が「分子の家族の特徴」で、どれが「どこにでも出る一般的な断片」かを見分けるのが難しい
- 方法（主張、要約の文の範囲）: 網のモジュール性の手法と分位 GAM（QGAM）で、「その出現の多さから期待されるより、網の上で位相的にまとまって（cohesive に）共有される」断片・中性損失を選ぶ。選ばれたものを部分網の「署名」（diagnostic reporter）とし、注釈の伝播の根拠にする
- 例（主張）: Alternaria の代謝物で、一般的な断片と、tricycloalternarene の家族に特有の reporter を分けた
- 読めていないこと（未確認）: 「cohesiveness」の式、網の作り方（辺のしきい値）、モジュールの分け方、QGAM の分位と説明変数、reporter の判定の基準、注釈の伝播に実際どう使うか（点の式か、人の判断の補助か）、定量的な評価（正解の順位などの指標があるか）。要約には構造の順位付けの評価は書かれていない
- 読み（解釈。未確認）: 中心の考えは「**出現の多さで割り引いた、家族の中への偏り**」で特徴に重みを付けること。0.495 系統の網の辺（修正 cosine、全ピークを同じ扱い）は、H2O の損失のような一般的な断片と家族に特有の断片を区別しない

### 1.2 MS2LDA / Mass2Motif（出典 2）
- 何をするか（確認）: LDA（話題モデル）で、スペクトルの集まりを「一緒に出る断片と中性損失の組」（Mass2Motif）に分解する。1 つのスペクトルに複数の Mass2Motif が入ってよい。教師なしで、構造の注釈は人が付ける（degree ≥ 10、つまり 10 本以上のスペクトルに出る Mass2Motif を MS2LDAvis で見て注釈した）
- 網との違い（確認、本文の序論と Discussion）: Molecular Networking は全体のスペクトルの類似が高いものしか束ねず、小さな部分構造を共有する分子を取りこぼす。MS2LDA は全体の類似が高くなくても部分構造で束ねる
- 効果（主張）: ビール 4 種で、構造を注釈した 30〜40 個の Mass2Motif がスペクトルの平均約 70% を説明した。比べると、MassBank・NIST への照合（正規化点 90%）で当たったのは 25%・6%。反応例: CHOOH の損失（Mass2Motif 262）は遊離のカルボン酸を示し、同定できたアミノ酸 18 個のうち 10 個に付いた
- 異なる装置・研究室への転用（主張）: GNPS・MassBank のデータでも、注釈した Mass2Motif が使えたと書く
- 前提（確認）: 複雑な混合物（多くの代謝物が断片化される）で最もよく働く。Mass2Motif の注釈は人手

### 1.3 MESSAR（出典 3）
- 何をするか（確認）: **構造の分かった参照スペクトル**から「MS/MS の特徴（最大 3 個）→ 部分構造」の関連規則を採掘し、未知のスペクトルに部分構造を推薦する。MS2LDA の Mass2Motif を人手でなく規則で注釈する用途も書く
- 学習データ（確認）: GNPS の正イオン Q-TOF の 4,138 本（Scheubert らの target と、断片木を並べ替えた decoy）。同じ構造のスペクトルをまとめて 3,146 本
- 特徴（確認）: 断片の質量（断片木で式を付けた断片）と、断片木の辺（＝損失）。全ピーク間の質量差は使わない（20 ピークで 190 通りになり、構造の情報の無い差ばかりになるため）
- 部分構造（確認）: CSI:FingerID の指紋 1,483 個（ECFP4 以外）を部分構造に直したものと、BRICS で 1〜2 本の結合を切った断片。炭素と酸素が 5 個未満の CHON の部分構造は捨てる
- 規則の選び方（確認）: 規則ごとに precision = TP/Supp(X)、recall = TP/Supp(Y)。target と decoy の分布を比べると recall の方がよく分かれる（decoy は 0.07 付近、target は 0.16 付近で右に長い裾）。recall の 1% FDR のしきい値として 0.20 を取り、規則 20,747 本から 8,378 本を残した
- 評価（主張）: 別の MassBank 5,164 本で、評価できた 4,743 規則の半分（2,364）が recall > 0.6。未知の 185 本（MassBank + CASMI 2017 の 25 本、学習と inchikey の第 1 ブロックで重なり無し）で「上位 3 に正しい部分構造が 1 つ以上」は MESSAR 42%、CSI:FingerID 52%、両方を合わせて約 50%。MESSAR は多環芳香・インドール・クロロベンゼン、CSI:FingerID はアミノ酸・窒素の官能基で強いと書く
- 前提（確認）: 正イオンの LC-MS/MS 向け。規則の数は学習の 3,146 構造で決まる

### 1.4 MolNetEnhancer・NAP（出典 4・5、前の調査の要約）
- MolNetEnhancer（#160 §1）: GNPS の網の家族（連結成分）ごとに、各ノードの in silico 候補を ClassyFire で分類し、最も多い分類を家族に付ける。構造の順位は直接は並べ替えない。家族の単位は**網の連結成分**（スペクトル同士の類似で決まる）
- NAP（#105 §1）: 隣のノードのライブラリ一致（Fusion）か、隣の in silico 候補の上位（Consensus）との Tanimoto で並べ替える。効果の大部分は Fusion から来る（#105 §6 の読み）

### 1.5 まとめ（解釈。未確認）
- 網の 4 手法（NAP・MolNetEnhancer・ZODIAC・ChemWalker、#160）は「同じ試料の中に類縁体の家族がある」ことを前提にする。v3 は fold 0 からの無作為の抜き出しで、問い合わせ同士の類縁体が少ない（#101: 相互最近傍の組の正解どうしの Tanimoto の中央値 0.24〜0.31、#160 §6）
- MS2LDA と MESSAR は、**断片・損失そのものを部分構造の証拠にする**。網（問い合わせ同士のつながり）が無くても、1 本のスペクトルに対して使える。MESSAR は構造の分かった参照から教師ありで学ぶので、この競技の train（構造ラベルつきの参照スペクトル）と同じ形のデータで作れる
- diagnostic reporters の「出現の多さで割り引いた家族への偏り」は、MESSAR の規則の選び方（一般的な特徴の規則は precision が低い）と同じ問題を、網の上で教師なしに解いたものと読める

## 2. 0.495 系統の網・nbz・lfus と、今回の案 rep の違い
（0.495 系統の網・nbz・lfus の中身は #160 §2・§3 と #150 の事前登録の本文による。rep の中身は §6）

1. **証拠の元（何と何を比べるか）**: 0.495 の網は**テストの問い合わせ同士**のスペクトル（修正 cosine ≥ 0.6・一致 ≥ 6）、nbz も問い合わせ同士（エントロピー類似の相互最近傍）、lfus は問い合わせと **train の参照スペクトル全体**の類似（類縁検索、上位 100）。rep は問い合わせのスペクトルを他のスペクトルと比べない。問い合わせの**個々の断片・中性損失**を、train の参照から数えた「家族（Murcko 骨格）×特徴」の表に引く。問い合わせ同士の類縁体の家族が無い集合（v3、#160 §6）でも 1 本ずつ使える
2. **特徴の重み（一般的な断片の扱い）**: 0.495 の網の修正 cosine と lfus のエントロピー類似は、一致したピークを強度だけで重み付けし、H2O・CO2 の損失のような一般的な特徴も家族に特有の特徴も同じに扱う。rep は特徴ごとに「家族の中での出現率 ÷ 全体での出現率」（§6.2 の式）で重みを付け、どこにでも出る特徴は比が 1 に近く寄与が小さい（出典 1 の考え、出典 3 の precision と同じ向き）
3. **伝えるもの（候補のどこを見るか）**: 0.495 の網は隣の上位 5 候補の Morgan 指紋との Tanimoto、nbz は隣のロジット、lfus は類縁体の構造との Tanimoto の s 重み付き平均。rep は**候補自身の Murcko 骨格**（家族）だけを見る。類縁体の構造との全体の似かたを使わない
4. **候補自身の参照の扱い**: lfus と 760347 型（ライブラリ一致で 1 位を上書き）は、候補の構造そのものの参照スペクトルが残っていればそれとの一致が効く（lfus の v3_c1 +0.025 には正解自身の他の装置の参照 296 本との一致が混ざる、#150）。rep は、候補 c の点を作るとき c の構造自身（inchikey14・key・rawkey のどれかで同じもの）の参照を表から引いて数える（leave-own-structure-out、§6.2）。そのため rep はライブラリ一致として働かない
5. **合わせ方と 1 位**: 0.495 の網は順位の z + λ·z（λ 0.35）、D-L1 の追加分は 1 位を固定。rep は lfus と同じ位置・同じ等重みの z 合成（`run.py` の `sanpier_mix` と同じ形、λ なし）。1 位の固定も上書きもしない
6. **定数**: rep は 0.495 系統の定数（0.6・6 ピーク・cos⁴・上位 5・λ 0.35・0.5 倍・23 個の変換質量）を 1 つも使わない。新しく決める値は §6.2 に列挙し、どれも v3 を見て選ばない

## 3. 760347 型（ライブラリ一致で 1 位を上書き）との違い
- 760347（日報 2026-11-19 夜）: 0.495 系統の写しに、外部ライブラリ 1,243,552 スペクトルで「sqrt cosine ≥ 0.80・4 ピーク以上なら 1 位に上げる」規則を足したもの（主張、日報の記述。ノートは今回読んでいない）

- rep は、(i) 上書きでなく z 合成の 1 項、(ii) 候補自身の参照を数えない（§2 の 4）、(iii) 骨格が同じ候補（異性体の多く）には同じ家族の証拠しか与えないので、異性体の間の順を rep が入れ替えることは無い（同じ家族の候補は同じ点。§6.4 で、この性質で届かない分子を数えた）

## 4. lfus の v3_c2n −0.0387 との関係

## 6. v3 で測る案（1 つ。書くだけで、実行していない）

### 6.1 名前とねらい
- **rep 段**: train の参照から「Murcko 骨格（家族）× 断片・中性損失」の出現を数え、出現の多さで割り引いた家族への偏りを、問い合わせの特徴ごとに引いて候補の家族の点にする。MESSAR（教師あり、特徴 → 部分構造）と diagnostic reporters（出現の多さで割り引いた偏り）を、網なしで 1 本のスペクトルに使う形にしたもの
- 構造の変更（新しい証拠の列）で、定数の写しではない。既存の score（FPNet の指紋の点）も「スペクトル → 部分構造」を学習したモデルなので、**情報が重なっている可能性がある（未確認）**。rep が足すのは、(a) 個々の質量の値そのもの（FPNet の入力の離散化とは別の、0.01 Da の特徴）、(b) 骨格という指紋のビットより大きな単位、(c) 決まった数え方で学習の揺れが無いこと

### 6.2 中身（事前登録の案。値は全部ここで決め、v3 を見て選ばない）
- 家族 F(s): 構造 s の Murcko 骨格（RDKit `MurckoScaffold.GetScaffoldForMol` の正準 SMILES）。環の無い構造は全部で 1 つの家族 ""（`reporter_reach.py` の `scaffold` と同じ定義）
- 参照: holdout の隠す規則を当てた後の train の参照（lfus と同じ `Library.representatives(exclude=印, key=<holdout>)` の代表スペクトル）。イオン化モードごとに別の表
- 特徴: 代表スペクトルの各ピークの m/z と、中性損失（前駆体 m/z − ピークの m/z、正のものだけ）を、0.01 Da の格子に丸めたもの（0.01 Da は `SearchCfg` の既定の tol と同じ値で、新しく選ばない）。ピークの強度のしきい値は付けない（ライブラリの配列〈`work/spec_mz.npy`〉に入っているピークを全部使う。その配列にどんな前処理が済んでいるかはこの調査では確かめていない）
- 数え方（構造の単位）: 構造 s が特徴 f を持つ ＝ s のそのモードの代表スペクトルのどれかに f がある。a(f, F) = 家族 F の構造のうち f を持つ数、n_F = 家族 F の構造の数、c_f = f を持つ構造の数、N = 構造の総数（モードごと）
- 偏り: r(f, F) = log((a + ½)/(n_F + 1)) − log((c_f + ½)/(N + 1))。½ と 1 は二項の比の Jeffreys 型の補正（足す数を v3 で選ばないために、慣用の値に決め打ちする）
- leave-own-structure-out: 候補 c が train の構造なら、c と同じ構造（inchikey14・key・rawkey のどれかが一致する構造、別名も）の寄与を a・n_F・c_f・N から引いてから r を作る。正解も他の候補も同じ扱い
- 候補の点: rep(c | q) = 問い合わせ q の特徴（q のスペクトルのどれかにある f、q のモードの表）のうち c_f ≥ 1 のものについての r(f, F(c)) の平均。F(c) が（自分を除いた後）表に無い候補は点を付けず、窓の中の点の平均（z = 0）にする。その候補の数を記録する
- 置き場所と合わせ方: lfus と同じ（prior の後・frag の前、上位 TOPN = 60）で z(prior 後の点) + z(rep) の等重み（`run.py` の `sanpier_mix` と同じ形）。1 位の固定・上書きはしない。frag 以降は対照と同じ
- 学習（勾配）は無い。表は holdout ごとに数え直す

### 6.5 train の構造への偏り（rep は train から数えた表なので測る）
- 理由: 表は train の構造の参照から作るので、「家族が表に大きく載っている候補」（train の構造そのもの、またはその仲間）を、そうでない候補（プールの train の外の候補）より上げる向きの偏りがありうる。class 2 の正解（train の外）を下げる危険（#144 の考え）
- leave-own-structure-out で「候補自身の参照」の分は除くが、家族の大きさの分は残る
- 測り方（#146 の d_seen と同じ定義を rep の点に当てる。`scripts/local_eval/dseen.py` の群と正解の除き方）: 窓の候補を S（fragnn の学習構造 T）・U（train ∖ T）・O（それ以外）に分け、正解を除いた候補で d_seen = mean(z | S) − mean(z | U)、d_dom = mean(z | U) − mean(z | O)。主の対比は Δ_seen = d_seen(rep) − d_seen(MetFrag-lite)。読む集合は #146 と同じ v3_c1 と e180_c2k、帯も #146 と同じ（下限 > 0 → higher_seen、上限 < 0 → lower_seen、それ以外 none）
  - 注: rep は fragnn の T を学習に使っていないので、rep にとって意味のある「見た／見ない」は「表に載った train の構造（S ∪ U）対 O」。そのため d_dom（U 対 O）を、rep については記録だけでなく読む値に足す。読む値を d_seen と d_dom の 2 つにすると多重比較になるので、事前登録の回でどちらを主にするかを 1 つ決める（推奨: rep では d_dom を主にする）
- 使い道（実行前に固定する案）: 採否は §6.3 の規則だけで決める。偏りの結果で rep の定義は替えない（替えるなら新しい Issue で事前登録してから）。higher なら「class 2 型の危険」として採用時の提出の事前登録に書く
