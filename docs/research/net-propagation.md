## 1. 文献の要点（網による伝播の型）
- **NAP**（出典 1、#105 §1 の要約）: 候補リストを、隣のノードの情報で並べ替える。Fusion（隣が構造の分かったライブラリの一致）と Consensus（隣の in silico 候補の上位との Tanimoto）。ベンチマークは cosine ≥ 0.6 の相手があるスペクトルだけを選んでいる。効果の大部分は Fusion（隣が既知構造）から来る（#105 §6 の読み）
- **ZODIAC**（出典 2）:
  - 何をするか（確認）: SIRIUS の分子式の上位（例 50）を候補にして、同じ測定の中の他の化合物の候補との断片木の類似（共通の断片と損失）を事前確率にし、Gibbs サンプリングで分子式を並べ替える（§2 冒頭、Fig. 6 の説明）。網の点（各化合物の候補の選び方の同時の組み合わせ）を最大にする問題は NP 困難で、だから Gibbs サンプリングを使う（§2）
  - 効果（主張）: dendroides で誤り率 50.25% → 3.05%（16.5 倍）、mice stool では 32.56% → 18.60%（§2）。本文は mice stool について「低品質のスペクトルを多く捨てたので、つながる化合物の網がずっと小さい」ことと「残ったスペクトルの質も悪い」ことを並べて書く（確認）。改善の大きさを網の大きさのせいだとは書いていない（確認）。比で見ると mice stool（1.75 倍）は NIST1950（9.57% → 6.38%、1.5 倍）より大きい。「網が小さいと効きが小さい」は、こちらの解釈で未確認
  - ライブラリの一致を anchor として入れても誤り率は良くならなかった（§2、Conclusion。確認）
  - 新しい分子式の報告には「その化合物の分子式が網の中で 5 個以上の化合物とつながる」を条件にしている。理由は、つながりが少ないと ZODIAC の結果が SIRIUS とほぼ同じになるから（§2「Novel molecular formulas」。確認）
  - 評価は SIRIUS の上位 50 に正解がある化合物だけ（Fig. 1 の説明。確認）
  - 前提（確認）: 「生物は限られた生合成経路から関連する代謝物を作る」（§2 冒頭）。同じ試料の中に類縁体が一緒に測られていることが、網の効く前提になっている
  - コード: SIRIUS に統合、GPL-3.0（Code availability。確認）。この調査では使わない
- **MolNetEnhancer**（出典 3）:
  - 分子の家族（GNPS の連結成分）ごとに、各ノードの in silico の構造候補（NAP・DEREPLICATOR など）を ClassyFire で分類し、最も多い化学分類を家族に付ける。家族の点 = その分類の数 / ノード数（例: 6 ノードで flavonoid が 2.25 → 0.375）（§2 と Fig. 2 の説明。確認）
  - 単独のノード（つながりなし）は候補 1 つで点 1 になりやすい、と注意を書いている（確認）
  - 構造の順位を直接並べ替える方法ではなく、家族の分類の多数決で注釈を補う（確認）。辺は cosine 0.6 超（Fig. 4 の説明。確認）
- **ChemWalker**（出典 4）:
  - NAP は情報を「ライブラリの一致の直接の隣」までしか伝えない。ChemWalker は、スペクトルの網と候補構造の類似を MetFusion の点の式で重みにしたグラフ上でランダムウォークし、ライブラリの一致（seed）から直接つながっていないノードにも伝える（abstract。確認）
  - NIST の 555 スペクトルの網で 27 種の RDKit 指紋を比べ、上位 10 候補の分類では NAP と統計的に区別できない（§3。主張）。改善点は速度・規模・保守性（abstract。確認）
- **まとめ（解釈。未確認）**: 4 本とも「同じ試料に類縁体が多く、網がつながる」ことを前提にし、効果はつながりの多い化合物・既知構造の隣（seed・anchor・Fusion）に集まる。ZODIAC は mice stool で網が小さいこととスペクトルの質の悪さを並べて書く（網の大きさと効きの関係はこちらの解釈で未確認）。0.495 の N-1c は NAP の Consensus 型（隣の問い合わせの候補の上位との Tanimoto）、D-L1 の (A) は Fusion 型、(C) の 2 段の伝播は ChemWalker の「直接の隣より先に伝える」に近い

## 3. nbz（#103）・lfus（#150）との違い（コードの行つき）
1. **辺の定義**: 0.495 は同じ付加イオンの修正 cosine ≥ 0.6・一致 ≥ 6 の全ての組（c23 L124–138）。nbz は同じイオン化モードのエントロピー類似度の**相互最近傍**だけ、しきい値なし（`run.py` L153–173 の `nbz_pairs` → `query_network.py` L50–56 の `sim_matrix`、L74–77 の `mutual_pairs`）。nbz では各分子の相手は高々 1 つで、似ていなくても必ずつながる（#101: v3_c1 は 42 組・84 分子がつながり、組の正解の Tanimoto の中央値 0.255、≥ 0.5 は 0 組）。0.495 ではしきい値に届かない分子はつながらない
2. **伝えるもの**: 0.495 は隣の**候補構造**（上位 5 の Morgan 指紋）との Tanimoto（c23 L445–466）。nbz は隣の**予測ロジット**を混ぜる z_i' = (z_i + s·z_j)/(1 + s)（`run.py` L138–150）。nbz は採点の前に FP の証拠そのものを書き換えるので、候補の窓の全行の点が変わる（`run.py` L351 で z を差し替えてから `score_window`）。0.495 は候補の集合を変えず、リストの順だけを変える
3. **合わせ方と λ の位置**: 0.495 は順位の z（z(−log 順位)）と網の点の z を λ で足す（c23 L152–154）。点の尺度を使わない。nbz には λ が無く、s/(1+s) がロジットの中の重み。lfus は z(prior 後の点) + z(N) の等しい重み（`feat/150-lfus` の `run.py` 20–22 行、384–388 行）で、点の尺度（prior 後）を使う
4. **1 位の保護**: 0.495 の網のうち素の N-1c は 1 位を替えられる。D-L1 の追加（A・B・C）は、N-1c が選んだ 1 位を替えられない（c23 L481–491、L542–546）。nbz・lfus には 1 位の保護が無い。nbz の v3_c1 は良 0・悪 10、lfus の v3_c2n は良 28・悪 40（`outputs/local_eval/nbz_v3_check.json`・`lfus_v3_check.json`）
5. **既知構造のノード**: D-L1 (A) は train の合成スペクトルを修正 cosine でつなぐ（c23 L357–419）。lfus は `casmi.library` の類縁検索（±200 Da、上位 100、エントロピー類似）で train の参照を取り、隠す規則を当てた後の train だけから取る（#150）。nbz には既知構造が無い。D-L1 (A) は v3 の隠す規則を持たないので、そのまま v3 に持ち込むと正解の参照を拾う（`exclude` が空、c23 L407・L503）
6. **段の位置**: nbz は score の段（prior・frag の前）、lfus は prior の後・frag の前、0.495 の網は全パイプラインの最終リスト（25 件）の後

## 4. FR 3-25（c28）
- 何をするか（確認）: FRNet（`model.py` の docstring: 断片で注釈した候補の分子グラフの GNN + 注釈したピークの transformer、c28 L80）で、リストの全候補に点を付け（c28 L132–158）、リスト全体で z 化し（c28 L196–199）、**3 位以下だけ** −順位 + 3.0·z で並べ替える（c28 L22、L24、L185–200）。1・2 位は動かさない。合わせ方は網と同じ「順位 + 重み × z」
- 学習（確認、`SOURCE.md`・`train_result.json`）: 全 train の構造ごとに 1 問い合わせ、候補は正解 + 同じ分子式の負例 最大 16（Tanimoto が近い 8 + 無作為）+ ±0.02 Da の別分子式 最大 4。負例は train の構造と公開の構造 DB（COCONUT・LOTUS・PubChemLite など）と Engine 1 の候補プールから。内部検証は構造の 4%（InChIKey14 のハッシュ）、12 エポック中の最良 9（val group MRR 0.8892）、RTX 4070 Ti SUPER で 3,182 s
- **v3 では FR の重みをそのまま測れない**（確認）: 全 train で学習しているので v3 の正解（fold 0 の構造）を見ている。測るなら fold-safe な学習（fold 0 を除く）が要る
- 自前の対応物: fragnn（#120、fold-safe、自前の学習）。v3 では v3_c1 +0.0261 [+0.0027, …]、enveda_v1 −0.0079 [−0.032, …] で不採用（`fragnn_v3_check.json`）。FR 3-25 との構造の違いは (i) fragnn は prior の前に点 s に等しい重みで混ぜ、窓の全行を動かす、FR は最終リストの 3 位以下だけを動かす、(ii) FR の負例は外部の構造 DB からも取る（fragnn の負例の作り方はこの調査では読んでいない）
