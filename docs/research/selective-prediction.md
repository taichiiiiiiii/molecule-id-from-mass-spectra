## 1. 文献

### 1.1 Jürgens, De Waele, Rakhshaninejad, Waegeman「When should we trust the annotation? Selective prediction for molecular structure retrieval from mass spectra」

- 出典: arXiv:2603.10950v2（2026-08-10）、https://arxiv.org/abs/2603.10950v2 、DOI 10.48550/arXiv.2603.10950
- ライセンス: CC BY 4.0（HTML 版の表示）。コード https://github.com/mkjuergens/Selective-MSMS は MIT（GitHub API の license）。チェックポイント・予測は Zenodo 10.5281/zenodo.19108280（中身は見ていない）
- 読んだ範囲: HTML 版の §1–§4、付録 §8.4（教師ありの組み合わせ）・§8.5（温度）・§8.6（別の候補集合）。付録 §5–§7（式の詳細・SGR の手順・構成）と §8.1–§8.3 は見出しを見ただけで、読んでいない
- 設定（§2.1、§2.6）: MassSpecGym（231,104 スペクトル、28,929 分子）。分け方は MCES 距離 10 以上で構造が重ならない train/val/test（17,556 test スペクトル、2,998 分子）。候補は同じ組成式で最大 256（主の設定）。**候補に正解が必ず入る閉じた設定**（§2.1「By construction, the true fingerprint satisfies y_i ∈ C_i」、§4 で「正解が候補に無い開いた設定は未解決」と自分で書いている）。モデルは 3 層 MLP（4096 ビットの Morgan 指紋、余弦類似度、順位の損失 T=0.003）と transformer、Deep Ensemble 5 本・MC Dropout 50・Laplace 50
- 確信度の定義（§2.3、表 1）: 検索の段の 1 次の量 κ_conf = 最上位候補の softmax 確率（T で温度づけ）、κ_gap = 上位 2 候補の類似度の差。2 次の量はアンサンブルの候補分布の全体・偶然・認識のエントロピー分解と順位の分散。指紋の段はビットごとの Bernoulli のエントロピー分解。入力の段は kNN 距離・Mahalanobis 距離
- 評価（§2.5）: リスク・カバレッジ曲線の面積 AURC、と relAURC =（AURC − oracle）/（random − oracle）（0 = 完全、1 = ランダムに棄てるのと同じ）。リスク制御は SGR（Geifman & El-Yaniv 2017）で、test を半分ずつ校正・評価に分け δ=0.001
- 結果（表 3、MLP Deep Ensemble、Hit@1 の損失）: relAURC は κ_ret^tot 0.347、κ_conf 0.366、κ_gap 0.439、**指紋の段は 0.92 前後（κ_bit^tot 0.917）でランダムに近い**、入力の距離は 0.98 前後。著者の読み: 「確信度は目的の損失と同じ段で測ったものが効く。指紋のビットの不確かさは検索の成否の代わりにならない（正解と競合候補の相対的な近さで決まるため）」。transformer でも順序は同じ（表 4、Hit@1 では κ_conf 0.356 が最良）
- §8.4: 教師ありの組み合わせ（ロジスティック回帰、特徴は s(1)・gap・log|C|・conf・エントロピー・順位の分散・ビット数など、正則化は val の log loss で選ぶ）は Hit@1 では単独の最良より少し悪く（MLP −0.014、transformer −0.007）、Hit@20 で約 0.045 良い
- §8.5: softmax 由来の量は評価の温度で変わり、最良は学習の温度付近（Hit@1）。gap と順位の分散は温度に依らない
- §8.6: 質量 ±10 ppm で取った候補（このコンペの窓に近い）では、どの量も悪くなる（MLP の Hit@1 で κ_conf 0.497、κ_gap 0.572、κ_ret^tot 0.479）。候補の数はほぼ全部が上限 256 に届き、手がかりにならない
- このコンペでの条件: 手法（AURC、確信度の定義）は式なので使える。コードは MIT。ただし (1) 閉じた設定の結果で、C2 型（正解がプールに無い）は扱っていない、(2) アンサンブルの 2 次の量は、手元の fold-safe なモデルが fold-0 の 1 本だけなので今は作れない、(3) 温度は選ばない（ハイパラ調整の禁止）。この文書では T=1 に固定した（§2.1）

### 1.2 Hoffmann ほか「High-confidence structural annotation of metabolites absent from spectral libraries」（COSMIC）

- 出典: Nature Biotechnology 40, 411–421 (2022)、https://www.nature.com/articles/s41587-021-01045-9 、DOI 10.1038/s41587-021-01045-9
- ライセンス: ページの表示は Open access（ライセンスの文言は抽出で確かめられなかった）。COSMIC は SIRIUS の中の機能で、**SIRIUS はこのコンペで使えない**（主催者の回答: 話題 751373 のコメント 3543071「correct, not allowed」。draft PR #215 の `docs/research/rules-and-deps.md` に引用、main には未マージ）。使えるのは考え方だけ
- 読んだ範囲: 要旨、Method overview、Method evaluation の前半、Discussion の一部（ページの抽出の頭と尾。補足表 1 の特徴の一覧は読んでいない）
- 要点: CSI:FingerID の 1 位（hit）だけを対象にし、並べ替えも捨てもしない。確信度 = PubChem の候補の点を囮の代わりにした E 値（対数正規の混合を核密度で）＋線形 SVM（特徴は 1 位と 2 位の点の差、断片木が説明した強度、指紋のビット数など）。**特徴の向きを前もって決めて強制する**（例: hit の点が高いほど確信度は下がってはならない）ことで過学習を抑える。候補が 1 つの分子は別の SVM。Platt scaling で確率に写す。評価は構造が重ならない 10 分割の交差検証と独立のデータ
- 要点（誤りの形）: 確信度の高い誤りの上位 9 件のうち 7 件は「正解が構造データベースに無い」もので、9 件とも正解の構造は hit によく似ていた。そのうち 3 組のスペクトルを比べると余弦は 0.85–1.00（Extended Data Fig. 4）。つまり**正解が候補に無いとき、似た構造の候補が自信をもって 1 位になる**。これは C2 型の振り分けで一番難しい場面と同じ
- このコンペでの条件: 「向きを決めた線形モデル」「1 位の点と 2 位の差」「候補が 1 つの分子の別扱い」は自前で書ける。E 値の考え方（PubChem の点の分布で 1 位の点を校正する）は、PubChem 層の窓の点の分布が手元にあるので試せる

## 2. v3 での測定（記録だけ）

### 2.1 定義（#216 で測る前に固定、コミット c9d5e93 の `scripts/local_eval/selpred.py` の docstring と同じ）

- 対照: `run.py --stages score,prior,frag`（`--logits-dir`・`--truth-dir` = `outputs/local_eval/<h>`）。`selpred.py` は run.py の関数で同じ手順を組み直し、run.py の既定の動きは変えていない
- L = frag 後の重複除去した上位 60。各候補の点 f = prior 段の z(s) + 0.15·pop（frag は同じ組成式の中で順を入れ替えるだけで f は変えない）
- κ_gap = f(L[0]) − f(L[1])（frag の入れ替えで負になりうる）、κ_conf = softmax(f over L, **T=1 固定**)[0]、κ_lib = lib_max（L の候補の参照スペクトルとのエントロピー類似度の最大、参照が無ければ 0。各集合の隠す規則を適用。run.py の lib 段の diag と同じ）
- |L|=1 → κ_gap=+∞・κ_conf=1、|L|=0 → 3 種とも −∞（1 位は不正解）
- 正解 = 公式 metric の鍵で rr=1。AURC は損失 1 − 正解、同点の中はランダムな順の期待値（厳密）。CI は分子の bootstrap 2000 回（seed 0）のパーセンタイル 95%
- 事前登録に書いていなかった扱い（完了レビュー 1 回目の指摘で開示）: bootstrap の回で値が有限でないもの（誤りが 0 か全部で relAURC が NaN の回）は CI の計算から除く（`selpred._pct`）。v3_c2_t10 は全部の回が NaN なので relAURC の CI は無し。ほかの 3 集合は、同じ seed の 2000 回で誤りが 0 か全部になる回が 0 回だった（per-molecule の CSV から数えた）ので、除いた回は無い
- AUC = P(κ_A > κ_B) + 0.5·P(同点)、A = 正解がプールにある型、B = v3_c2_t10。主は A = v3_c1u_t10、副は enveda_v1u_t10・v3_c2nu_t10

読み（記録）:

- **κ_lib（窓の上位 60 の lib_max）は 3 集合ともランダムより悪い**（relAURC の CI の下限 > 1）。lib_max が高い分子ほど対照の 1 位が外れている。理由はこの測定では分からない（仮説: lib_max の候補が 1 位と別の候補のとき、対照はライブラリを使っていないので、参照のある異性体が近くに居る難しい分子ほど lib_max が高い。確かめていない。確かめるなら「lib_max の候補 = 1 位か」を事前登録した別の量として測る）
- 正解の参照を全部隠した 2 集合（enveda_v1u_t10・v3_c2nu_t10）でも同じ向きなので、正解自身の参照で lib_max が上がっていることでは説明できない

### 2.4 C2 型（正解がプールに無い）対ほかの型: プールの 1 位の確信度の AUC

AUC = P(κ_A > κ_C2) + 0.5·P(同点)。0.5 = 区別できない、1 = C2 型の確信度がいつも低い。

| A（正解がプールにある型） | 役割 | κ_gap AUC [CI] | κ_conf AUC [CI] | κ_lib AUC [CI] |
| --- | --- | --- | --- | --- |
| v3_c1u_t10 | 主 | 0.6738 [0.6293, 0.7174] | 0.7247 [0.6804, 0.7664] | 0.7612 [0.7103, 0.8107] |
| enveda_v1u_t10 | 副 | 0.6439 [0.5987, 0.6903] | 0.7012 [0.6551, 0.7435] | 0.4406 [0.3933, 0.4911] |
| v3_c2nu_t10 | 副 | 0.5659 [0.5189, 0.6121] | 0.6306 [0.5867, 0.6724] | 0.4113 [0.3684, 0.4567] |

中央値: v3_c2_t10 の gap 0.413・conf 0.160・lib 0.567、v3_c1u_t10 は 0.923・0.273・0.829、enveda_v1u_t10 は 0.886・0.261・0.531、v3_c2nu_t10 は 0.539・0.240・0.523。

読み（記録）:
- 「確信度が低いほどプール外」は gap と conf では 3 つの比べ方すべてで成り立つ（CI の下限 > 0.5）。ただし、正解がプールにあって参照が無い v3_c2nu_t10 との差は小さい（conf 0.63、gap 0.57）。1 位の確信度だけで「プール外」と「プールにあるが難しい」を分けるのは弱い
- **κ_lib は主の比較（0.76）では一番よく分けるが、参照を隠した 2 集合が相手だと 0.5 を下回る（0.44・0.41）**。主の比較で効いているのは「正解の参照があるか」という集合の作り方（v3_c1u_t10 は enveda の参照だけを隠す、v3_c2_t10・enveda_v1u_t10・v3_c2nu_t10 は正解の参照を全部隠す。enveda_v1u_t10 は hide_rule.json が無く、`library.hide_rule` の既定 rule=all）で、答えの出所ではない、と考える（**仮説**。副の AUC が 0.5 を下回ることとは合うが、参照の有無だけを変えて比べた測定ではない。0.5 を下回る理由、つまり v3_c2_t10 の lib の中央値 0.567 が enveda_v1u_t10 の 0.531・v3_c2nu_t10 の 0.523 より高い理由も説明できていない）。lib_max だけで振り分けを学習すると、skill の注意の近道（「ライブラリ一致が無い → 外部の候補」）をそのまま覚える。#216 の事前登録の注意どおりの結果
- 1.1 の論文の「指紋のビットの不確かさは検索の成否の代わりにならない」は、ここでは測っていない（fold-0 の 1 本ではアンサンブルのビットの分散が作れない）。測ったのは検索の段の 1 次の量だけ

## 3. B8 の振り分け器の案（1 つ。測定値で特徴を選び直さない）

この案の特徴と組み合わせは、§1 の文献と #216 の事前登録の注意から決めたもので、§2 の数字を見て足したり外したりしていない（κ_lib を外さず「参照の有無」を学習の組み合わせ側で釣り合わせるのはそのため）。

- 目的: 分子ごとに「正解がプールの窓にある確率」p を出し、プールの一覧と PubChem 層の一覧の合成に使う（しきい値で切らない。合成の形は別の Issue で事前登録する）
- 特徴（向きを前もって決める。COSMIC の向きの強制に倣う。+ は「プールにある」側に効く向き）:
  1. プール側の 1 位の κ_conf（+）・κ_gap（+）
  2. PubChem 層の窓（プールにあるキーを除く）の 1 位の同じ 2 量（−）
  3. プールの 1 位と PubChem 層の 1 位の点の差（f·z の同じ尺度、0.479 版の rel と同じ量。+）
  4. κ_lib（+）
  - §2.3 の仮説から思いついた「lib_max の候補がプールの 1 位か」は、§2 の結果を見た後の量なので**この案には入れない**（入れるなら別の Issue で事前登録して測る）
  5. log（プールの窓の大きさ）・log（PubChem 層の窓の大きさ）（向きは決めない＝符号を制約しない。1.1 §3.3 で候補の数は手がかりになるが §8.6 の質量の窓では効かないため）
  - 指紋のビットの不確かさ（ビットごとのエントロピー）は入れない（1.1 の表 3 で検索の成否にほぼ効かない。fold-safe なアンサンブルも無い）
- モデル: 向きを制約したロジスティック回帰（正則化 C=1 固定、温度・しきい値は選ばない）。1.1 §8.4 で Hit@1 では教師ありの組み合わせが単独の量に勝たなかったので、比べる相手として「κ_conf だけ」の 1 変数モデルを同じ手順で必ず並べる
- 学習の組み合わせ（答えの出所 × 参照の有無の 4 型、**比率 1:1:1:1 を前もって決める**）: (a) プールにあり・正解の参照あり（他の装置、v3_c1u 型）、(b) プールにあり・正解の参照なし（v3_c2nu 型）、(c) プールに無く PubChem 層にだけある・参照なし（v3_c2 型）、(d) プールにあり・参照なし・enveda の装置（timsTOF）の問い合わせ（enveda_v1u 型。v3_c2nu_t10 の問い合わせは Orbitrap・QTOF などが主）。「プールに無く参照がある」は train の参照があればプールに入るので作れない
- 漏れ: 学習も評価も fold-0 の保留側の構造だけ（fold-0 のモデルのロジット）。構造の鍵の hash で 2 つに分け（分け方は実装の前に固定）、片方で学習、もう片方で 4 型すべてを評価する。v3_*_t10 の今の分子は評価側に入れない（新しい分子で 1 回だけ）。fold-0 の保留側に、まだ使っていない構造が 4 型を作れるだけ残っているかは数えていない（実装の前に数える）
- 採否の規則（skill の規則と同じ形、実装の前に Issue で確定）: 評価側の 4 型すべてで「新 − 対照」の 95% CI の下限 ≥ −0.02、かつ 1 つ以上で下限 > 0。1 型でも欠けたらコードが採用を拒む
- 分かっている危うさ: §2.4 のとおり 1 位の確信度は (b) と (c) を弱くしか分けない。分けられない分は PubChem 層側の量（特徴 2・3）に頼ることになり、その効き目はまだ測っていない
